# Аудиорегрессии Феникса

Отдельный локальный прогон настоящего ASR **без микрофона, воспроизведения и реальных
действий**. Обычный `python -m pytest tests/ -q` тестирует контракты раннера с fake
backend; это не измерение качества распознавания. Тяжёлый прогон не добавлен в CI
или `check_all.py`: их окружение специально остаётся лёгким.

## Быстрый старт — Windows, активная .venv311

Из корня проекта, после обычной установки runtime-зависимостей Феникса:

```powershell
python scripts/audio_regression.py prepare
python scripts/audio_regression.py run
$LASTEXITCODE
```

`prepare` использует установленный **русский системный голос Windows WinRT**.
Голос не проигрывается. Если его нет, команда завершится BLOCKED; можно установить
русскую речь средствами Windows или использовать собственные WAV (ниже).
Проверяется реальный синтез, не подстановка эталонного текста в ASR.

По умолчанию: 9 сценариев × 3 варианта = **27 кейсов / 51 аудиоход**.
Записи создаются один раз и переиспользуются. После изменения scenarios.json нужен
новый `prepare`: раннер сверяет версию, SHA256 сценариев и каждого WAV.
Перегенерация не перезаписывает corpus.json до успешного завершения; старый корпус
остаётся валидным при ошибке. Возможные неиспользуемые WAV можно удалить вместе
со всем локальным каталогом и повторить prepare.

WAV/корпус/отчёт находятся в `USER_DIR/audio-regression` — обычно
`%APPDATA%\Phoenix\audio-regression`, с учётом штатных fallback путей paths.py.
**Личные настройки/профили не загружаются**, используется DEFAULT_CONFIG и фиксированные
тестовые приложения. Это воспроизводимый baseline, не копия твоих текущих слайдеров.
Другой каталог можно задать **одинаково в обеих командах**:

```powershell
python scripts/audio_regression.py prepare --workdir .audio-regression
python scripts/audio_regression.py run --workdir .audio-regression
```

`.audio-regression/` и `audio-regression/` исключены из Git и snapshot. Произвольный
каталог внутри репозитория автоматически не исключается — не складывай туда записи.
В ZIP обновления входят только исходники/сценарии/документация, не модели/WAV/отчёты.

## Модели — уже установленные, без сетевых скачиваний

Для полного профиля нужны Vosk, faster-whisper/ctranslate2, onnxruntime и локальные
модели Vosk, Whisper (CTranslate2), Silero VAD. Они устанавливаются обычным runtime
Феникса; requirements-ci для этого недостаточно. Если первый запуск приложения
ещё скачивает модели — дождись его завершения до аудиотеста.

- Vosk ищется в `PROGRAM_DIR/models/vosk-model-small-ru-0.22`, затем `models/…`
  проекта. Путь должен быть ASCII. Другую папку укажи `--vosk-model C:\Models\vosk`.
- VAD ищется штатным `vad._find_model()` в установленных локальных путях.
  Раннер отключает auto_download; отсутствие/ошибка/fallback = BLOCKED.
- Whisper ищется в полном локальном snapshot модели из DEFAULT_CONFIG, в штатном
  `PROGRAM_DIR/whisper-cache`. При нестандартном кэше или другой модели используй
  `--whisper-model`: **папка** с model.bin, config.json, tokenizer.json и остальными
  файлами CTranslate2, а не имя модели для Hugging Face.

```powershell
python scripts/audio_regression.py run --whisper-model C:\Models\whisper-small
python scripts/audio_regression.py run --vosk-model C:\Models\vosk --device cuda
```

По умолчанию CPU — воспроизводимо и без обязательной CUDA; на большой Whisper-модели
это медленно. `--device auto|cuda` разрешены; штатный Whisper может откатиться с GPU
на CPU. Время wall_ms тогда нельзя выдавать за скорость GPU. Раннер блокирует
исходящие TCP-соединения и передаёт local_files_only=True загрузчику Whisper.
Он не вызывает скачивание Vosk, не запускает Ollama/облачные API и не меняет config.json.

Явно сокращённые диагностические профили:

```powershell
python scripts/audio_regression.py run --asr vosk
python scripts/audio_regression.py run --asr vosk --no-vad
python scripts/audio_regression.py run --case timer_units
```

Первый не проверяет Whisper, второй — ещё и VAD. Фильтр выбирает сценарий либо
полный ID кейса, например `timer_units--auto--clean`. Отчёт показывает выбранное/
общее число кейсов и coverage; частичный PASS не равен полной проверке.
Ошибки/fallback VAD или Whisper **включённого** профиля не превращаются в PASS.

## Корпус: синтез и собственный голос

Варианты: clean, quiet (−12 dB), noise (белый шум 20 dB SNR, seed 42).
Тестовые тишина и тихий шум генерируются локально. WAV нормализуются в PCM16,
mono, 16 kHz. Поддерживаются входные PCM WAV 8/16/24/32 bit, mono/stereo;
длительность одного файла до 30 секунд, ограничение исходного WAV 12 МБ.
Это ограниченный набор, а не реалистичная модель всей комнаты/сильного шума.

```powershell
python scripts/audio_regression.py prepare --voices Pavel,Irina
python scripts/audio_regression.py prepare --variants clean
```

Только установленные русские голоса; отсутствующий запрошенный голос — BLOCKED.
Два голоса дают вдвое больше кейсов. По умолчанию auto выбирает один русский голос.

Для человеческих записей создай каталог, например C:\VoiceTests\fenix:

```text
open_app/01.wav       # «Феникс открой»
open_app/02.wav       # «Блокнот»
timer_units/01.wav    # «Феникс поставь таймер»
timer_units/02.wav    # «На десять»
timer_units/03.wav    # «Минут»
...
```

Все тексты/порядок ходов — в `scenarios.json`. Нужен отдельный WAV **каждого речевого
хода** каждого сценария; тишину/шум записывать не надо. Микрофон раннер не включает.

```powershell
python scripts/audio_regression.py prepare --recordings C:\VoiceTests\fenix --workdir C:\VoiceTests\corpus
python scripts/audio_regression.py run --workdir C:\VoiceTests\corpus
```

Недостающие записи **не заменяются синтезом**, получается BLOCKED. Не меняй ожидания
сценария под ошибочную расшифровку ради зелёного результата. Если сценарий должен
проверять новую фразу — сначала обнови его контракт и fast-тесты, затем корпус.
Корпус человек/синтез лучше хранить раздельно через --workdir.

## Что именно проверяется

1. Реальный Listener callback → VAD и хвост → AcceptWaveform/Result Vosk.
   Микрофонный и файловый пути используют общий `_consume_audio`.
2. Настоящие confidence/PCM gate и, в hybrid, уточнение Whisper в `Jarvis._process`.
   Текст ожидаемой команды никогда не передаётся распознавателю как prompt/результат.
3. Реальные числовая грамматика, IntentHandler.handle, cancel/pending/compound/
   clarification/fast. Это **намеренно сокращённый pipeline**, не полный реестр.
4. Известные фикстуры приложений Блокнот/Steam вместо сканирования твоих программ.
   Открытие/таймер заменены журналом в памяти. memory/mood записи отключены,
   нет Observer, личных профилей, GUI, потоков индексатора, Speaker или LLM.
5. На каждом ходе проверяются действия, pending-slot, при необходимости вопрос
   и wake-маршрутизация. Отсутствие endpoint на ожидаемой речи — FAIL; endpoint
   на отрицательных тишине/шуме — тоже FAIL, даже если действие затем отклонено.

Каждый независимый кейс получает новый sandbox и VAD; между ходами сбрасываются
Vosk/буфер, но сохраняется диалог и ограниченное ожидание. Перед WAV добавляются
512 ms тихого фона для калибровки, после — 2304 ms для настоящего endpoint;
уровень dither 15 PCM предотвращает штатный режим «мёртвого микрофона».
Последний блок дополняется нулями до 2048 samples. FinalResult искусственно
не вызывается. Ожидания не переписываются при ошибке декодирования.

## Результат и приватность

- **0 / PASS** — все выбранные кейсы прошли в выбранном профиле.
- **1 / FAIL** — ASR/маршрутизация/уточнение/действие не совпали с контрактом.
- **2 / BLOCKED** — нет корпуса/моделей/голоса/backend, повреждение WAV, ошибка
  загрузки/inference, VAD выключился на fallback и т. п. Измерение не состоялось.

`reports/latest.json` в workdir содержит версию, платформу, SHA256 корпуса/WAV,
охват, результаты и ошибки каждого проверенного хода. После первой ошибки в кейсе
оставшиеся ходы не исполняются; они **не считаются прошедшими**. Другие кейсы
продолжаются, если не произошло блокирующей ошибки backend. При BLOCKED последний
отчёт заменяется явно заблокированным результатом с passed=0, не старым зелёным.

По умолчанию нет расшифровок, ответов, целей открытия и текста напоминания.
Для локальной диагностики можно явно включить `--include-transcripts` или задать
`--report C:\VoiceTests\report.json`. Такие отчёты могут содержать личную речь —
не публикуй их автоматически. Файлы никуда не отправляются.

`audio_ms` endpoint — позиция в поданном аудио с добавленным фоном/хвостом,
`wall_ms` — время вычислений, включая холодные эффекты конкретного запуска.
Это **не** задержка «конец речи → слышимый ответ», не WER и не бенчмарк GPU/CPU.
Для сравнения скоростей нужны одинаковые модели, железо, corpus/profile и прогрев.

## Границы и следующий этап

Не проверяются физический микрофон/драйвер/комната, TTS-звучание/тембр, эхо,
barge-in, задержки озвучки, GUI, парольный ввод, весь реестр, профили и LLM.
Для них остаётся короткая ручная приёмка на Windows; автопрогон снимает повторение
поддержанных командных сценариев, а не все голосовые проверки.

Полный Windows-прогон с настоящими моделями при разработке этого блока не запускался.
Fast-тесты на Linux не доказывают качество распознавания. Следующий согласованный
блок — GUI: сначала работоспособность/удобство, затем оформление (см. PLAN.md).
