# Тесты Феникса

Здесь собраны **все** проверки проекта. В корне остались только точки
входа: `check_all.bat` (запускает всё) и `check_syntax.py` (проверка
синтаксиса — им пользуется и CI, и `install.bat`).

## Карта

| Что | Где | Как запускать |
|---|---|---|
| Юнит-тесты (pytest) | `tests/test_*.py` | `python -m pytest tests/ -q` |
| Интент-тесты (39 сценариев) | `tests/test_intents.py` | `python tests/test_intents.py [--llm] [--network] [--voice] [-k фильтр]` |
| Стресс-тест (100 ситуаций) | `tests/stress_intents.py` | `python tests/stress_intents.py` |
| **Всё сразу** | — | `check_all.bat` (или `python check_all.py`) |
| Ручные прогоны | `tests/manual/` | вручную: микрофон / браузер / ONNX |

## Правила

* **Новый pytest-тест** — файл `tests/test_<модуль>.py`, функции `test_*`.
  Это единственный вид, который подхватывает `pytest tests/`.
* **Ручной прогон** (нужен микрофон, браузер, железо) — `tests/manual/`
  и имя **без** префикса `test_` (например `vad_live.py`), чтобы pytest
  не запускал его случайно. В начале файла — `sys.path.insert` до корня
  проекта, иначе `import jarvis` не найдётся.
* **Скрипт-раннер** (свой харнес, многошаговые прогоны, свои логи) —
  имя без префикса `test_` либо запись в `collect_ignore` в
  `tests/conftest.py` (так исключён `test_intents.py`, имя которого
  историческое и упоминается в документации).

## Ручные прогоны (`tests/manual/`)

Запускать руками (нужен живой рабочий стол), pytest их не подхватывает:

* `uia_dump.py` — дерево UIA активного окна браузера: что вообще видно
  (Edit/Document/Tab/Button).
* `uia_close_probe.py` — вкладки, которые видит UIA, и кнопки закрытия
  внутри них; `python tests/manual/uia_close_probe.py --close` — реально
  закрыть вкладку по «ютуб» (без флага — только смотрит).
* `uia_manual.py`, `vad_live.py`, `vad_debug.py` — UIA, микрофон, VAD.

## Зависимость от окружения

Не всё можно проверять одинаково на всех машинах — часть проверок
подстраивается под окружение:

* **UIA (окна браузера)** — нужна библиотека `uiautomation`. Если её нет
  (CI-раннер, «голая» Windows), команды «какие вкладки открыты», «какой сайт
  открыт», «прочитай окно» отвечают понятным отказом «UI Automation
  недоступна...». Именно это и проверяют пять ситуаций `uia_*` стресс-теста:
  ожидания подменяются по ответу `jarvis.uia.is_supported()` — тому же
  признаку, на который смотрят сами команды. Локально, где библиотека есть,
  те же ситуации читают настоящее окно браузера. Потолок отзывчивости
  у них тоже свой — 15 с вместо 5: рабочий стол читается «как есть».
* **Звук, ONNX, GUI** — пропускаются штатно через `pytest.skip(...)`
  в `test_vad*.py`, `test_prosody.py`, `test_tts.py`, `test_gui_wiring.py`.

Набор ситуаций при этом всегда один — ровно **100** (константа
`EXPECTED_CASES` в `tests/stress_intents.py`).
