Феникс управляет компьютером по-русски: открывает приложения, ставит таймеры,
меняет громкость и выполняет настроенные тобой сценарии. С ним можно и поговорить —
для этого подключается локальная модель через Ollama.

**Обычным командам не нужна LLM. Разговор — отдельная возможность, а не условие запуска.**

[Установить](#quickstart) · [Что попробовать](#commands) · [Руководство](docs/USER_GUIDE.md) · [Если не запустилось](#help) · [Тесты на GitHub](https://github.com/BobLoTiK/jarvis-fenix/actions/workflows/test.yml)

<a id="commands"></a>
## Начни с того, что и так делаешь каждый день

> Феникс, открой блокнот.  
> Феникс, поставь таймер на пять минут.  
> Феникс, громкость пятьдесят.

Те же запросы можно написать во вкладке **Диалог**. Если голосовая команда не
сработала, текстовый ввод помогает отделить проблему микрофона от обработки запроса.
После обращения действует окно диалога: в нём не нужно каждый раз повторять имя.

Необязательно сразу называть всё. После «Открой» Феникс может спросить приложение,
после таймера без времени — уточнить длительность. Это работает для поддержанных
команд, а не для любого запроса. «Отмена» сбрасывает такое уточнение.

[Все команды и их ограничения →](docs/USER_GUIDE.md#commands)

### Повторяется каждый день? Дай этому свою фразу

В **Моих командах** можно собрать от одного до шести действий без Python и
терминала. Например, связать «Пора работать» с открытием нужного приложения и
установкой громкости. Действия выбираются из поддержанного списка; фразу можно
проверить отдельно, ничего не запуская.

[Как устроен редактор сценариев →](docs/USER_GUIDE.md#custom-commands)

## Главная — не чат

На Главной — птица Феникса, аура, время и состояние ассистента. Рядом доступны
микрофон, переход в диалог и остановка речи. Задачи и быстрые действия добавляются
как необязательные виджеты; по умолчанию Главная не заполнена карточками.

Переписка живёт отдельно, в **Диалоге**. Настройки микрофона, голоса и персоны —
в своих разделах. Две темы, **«Сумерки»** и **«Фарфор»**, используют общий медный
акцент. Раскрытая боковая панель сдвигает содержимое, а не ложится поверх него.

[Интерфейс и настройки →](docs/USER_GUIDE.md#gui)

<a id="quickstart"></a>
## Запустить у себя

**Windows 10/11 x64.** Микрофон нужен для голосового ввода, для текста — нет.
Распознавание и озвучка работают локально после подготовки моделей. Видеокарта
NVIDIA не обязательна; нагрузка и скорость зависят от выбранных компонентов.

### Через установщик

1. Открой [Releases](https://github.com/BobLoTiK/jarvis-fenix/releases) и скачай
   **`Феникс_Setup.exe`**, если он приложен к выбранной версии.
2. Установи Феникса и запусти ярлык. Первый запуск подготавливает Python-окружение,
   зависимости и модели. Для этих загрузок нужен интернет.
3. Во вкладке **Микрофон** проверь уровень, затем попробуй команду с блокнотом.
   В **Голосе и звуке** выбери озвучку; в **Персоне** — имя и стиль общения.

`Феникс.exe` — лаунчер, а не полностью автономный EXE со встроенными моделями.
Если установщик в релизе отсутствует, ниже есть запуск из исходников.

**Проверка установки на чистой Windows ещё продолжается.** Собранный Setup и
прошедшие автотесты сами по себе не подтверждают успешный первый запуск.

### Из исходников

Установи [Python **3.11.9**](https://www.python.org/downloads/release/python-3119/).
Для текущего Windows/Vosk-стека не заменяй его на 3.13/3.14 без отдельной проверки.
Затем в PowerShell:

```powershell
git clone https://github.com/BobLoTiK/jarvis-fenix.git
cd jarvis-fenix
py -3.11 -m venv .venv311
.\.venv311\Scripts\python.exe -m pip install --upgrade pip
.\.venv311\Scripts\python.exe -m pip install -r requirements.txt
.\.venv311\Scripts\python.exe launcher.py
```

Активация окружения не требуется. Для следующих запусков можно использовать
`start_fenix.bat`; `start_fenix_debug.bat` оставляет консоль с диагностикой.
Подробная подготовка из исходников также доступна через `install.bat`.

### Если хочется разговаривать, а не только давать команды

Нужны [Ollama](https://ollama.com/download) и скачанная языковая модель.
Само наличие Ollama ещё не означает, что модель установлена.

В актуальном мастере подготовки можно вернуться после установки Ollama, нажать
**«Проверить»** и выбрать локальную модель: уже скачанную или один из предложенных
вариантов Qwen2.5 Instruct. Новая загрузка начинается только после подтверждения;
настройку можно пропустить. Ранее выбранная установленная модель не заменяется.

Это поведение относится к [обновлённому мастеру](docs/BOOTSTRAP_PYTHON_OLLAMA_UPDATE.md),
а не автоматически ко всем старым EXE. Для ручной настройки укажи в Фениксе точный
тег установленной модели и адрес сервера — по умолчанию `http://127.0.0.1:11434`.
[Инструкция Ollama, включая команды для старых сборок →](docs/USER_GUIDE.md#ollama)

Режимы переключаются в интерфейсе или голосом: **«Режим команд»** — без LLM,
**«Режим ИИ»** — диалог, **«Режим комбо»** — оба пути; комбо выбран по умолчанию.
Качество ответов зависит от модели. Наличие её в списке не гарантирует, что
компьютеру хватит памяти для работы с ней.

<a id="privacy"></a>
## Что остаётся на компьютере, а что использует сеть

**На компьютере:** VAD/Vosk и необязательный Whisper для распознавания;
Silero, Piper, WinRT или SAPI для речи. В режиме auto порядок озвучки —
Silero → Piper → WinRT → SAPI. Доступность голоса зависит от установленных компонентов.

**По умолчанию локально:** Ollama и контекст диалога. Если задать удалённый
`ollama_url`, запросы и контекст будут обрабатываться уже на том сервере.

**Сеть нужна:** для первоначальных загрузок, погоды, курсов валют и открытия
онлайн-ресурсов. Поэтому «локальный» здесь не означает «любая функция без интернета».

Настройки, профили и история обычно хранятся в **`%APPDATA%\Phoenix`**;
модели и кэши — в ASCII-путях, обычно **`C:\ProgramData\Phoenix`**.
Observer и векторная память выключены по умолчанию. Сохранение фактов не обучает
веса LLM; смена модели не должна стирать данные самого приложения.

Для опасных действий предусмотрены проверки; парольная защита действует, если
настроен пароль. Это не гарантия безошибочного выполнения любой команды.
[Приватность, память и защита действий →](docs/USER_GUIDE.md#safety)

<a id="help"></a>
## Если что-то пошло не так

**Не открывается окно.** Посмотри `logs\launcher.log` в папке установки.
Если `.venv311` уже подготовлена, запусти оттуда `start_fenix_debug.bat`.
Логи основного приложения обычно находятся в `%APPDATA%\Phoenix\logs`.
Не удаляй профили и историю ради повторной попытки.

**Не слышит.** Сравни одну команду голосом и текстом. Проверь устройство во
вкладке **Микрофон** и разрешение на доступ к микрофону в Windows.

**Команды работают, диалога нет.** Проверь выбранный режим, сервер Ollama и
точный тег скачанной модели. Это отдельный шаг, не часть установки Python.

[Подробная диагностика](docs/USER_GUIDE.md#troubleshooting) · [Сообщить о проблеме](https://github.com/BobLoTiK/jarvis-fenix/issues/new)

В сообщении полезны версия сборки, шаги повторения, скриншот и относящийся к сбою
фрагмент лога. Перед публикацией убери пароли, личные сообщения и другие секреты.

<a id="development"></a>
## Для тех, кто хочет менять Феникса

В основе — Python 3.11, Flet 1.0.x, Vosk/VAD, опциональный faster-whisper,
Ollama и несколько TTS-движков. Распознавание, обработка команды и речь — разные
части конвейера: замена модели диалога не требует менять всё приложение.

<details>
<summary><b>Проверки и сборка из корня проекта</b></summary>

После установки зависимостей для разработки (`requirements-dev.txt`):

```powershell
# Синтаксис, pytest, интент-сценарии и стресс-тесты
.\.venv311\Scripts\python.exe check_all.py

# Снимок обновляется после изменений
.\.venv311\Scripts\python.exe snapshot.py
.\.venv311\Scripts\python.exe snapshot.py --check

# Preflight ресурсов, без сборки EXE
.\.venv311\Scripts\python.exe scripts/build_setup.py --check
```

Полная сборка: `scripts/build_setup.py`, Windows, build-зависимости и Inno Setup 6.
В GitHub Actions ручной **build-release** публикует Artifacts без публичного
Release; push тега `v*` дополнительно создаёт Release. Пересборка нужна для
изменений встроенного в EXE лаунчера, не для обновления этого README.

Unit-тесты не заменяют микрофон, звучание TTS, настоящий Flet-клиент и чистую
Windows-установку. Для отдельной аудиоприёмки есть [аудиорегрессии](tests/audio/README.md).

</details>
