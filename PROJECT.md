# PROJECT — текущее состояние Феникса

## Цель и источники правды

Феникс развивается к JASTIN — видению работодателя. Максимально реализуем
целевые возможности, не выдавая их за существующие. Детали/источники:
[PLAN](PLAN.md), [целевая матрица](docs/PHOENIX_JASTIN_RECONCILIATION.md),
[оригиналы требований](docs/reference/README.md).

Этот документ — фактическая база; AGENTS — контракты, NEXT_STEPS — ближайший
блок, ARCHITECTURE — карта кода. История — CHANGELOG, не обязательна для входа.

## Статус текущей рабочей копии

| Область | В исходниках | Не подтверждено / следующий шаг |
|---|---|---|
| Запуск Windows | Bootstrap Python/Ollama, VC++/HTTPS/Flet preparation, TTS readiness и Whisper CPU fallback | Чистая установка/новые EXE/Setup; полный GUI-readiness handshake ещё не реализован |
| Аудио | Optional Piper AEC3, bounded capture worker/epoch/gap/pre-roll; диагностика Piper/Silero | Последний пакет пользователь ещё не проверял; живое AEC не принято |
| TTS | Silero → Piper → SAPI, общий PCM и per-call token; WinRT TTS удалён | Новый bounded streaming и fade-out не реализованы; применение Silero rate проверить |
| GUI/команды | Flet, Главная/Диалог/редактор/звук/профиль/настройки, typed static steps и уточнения | Целевая Windows UI/DPI/tray/audio-приёмка остаётся |
| Память | JSON, ограниченный контекст, опциональный local RAG/Observer | SQLite/SQLCipher/DPAPI, целевые embeddings и контролируемое обучение по R4 |
| Целевая архитектура | Рабочие внутренние модули и существующий pipeline | voice_core/Event Bus/SDK/биометрия/Trust/новый GUI/router — план R2–R6 |

Пользователь отложил Windows-аудио и Setup-проверки; это не их отмена.
Предыдущие AEC-пробы улучшили работу, но оставались ложные перебивания;
«х» в «их» — гипотеза для воспроизведения, не доказанная причина.
Ни новая документация, ни portable tests не подтверждают установку последнего пакета.

WinRT удалён только из TTS. `tts_backend=winrt` читается как auto с предупреждением
без записи конфига при чтении. WinRT Media Control сохранён. SAPI без PCM —
диагностические метаданные, не полный AEC reference. Оценочный render timestamp
не является аппаратной DAC/ADC синхронизацией; loopback/виртуального кабеля нет.

Следующий инженерный блок: [NEXT_STEPS](docs/NEXT_STEPS.md).
Снимок исключает локальные .env/.env.*/.envrc; их содержимое не редактируется.
Текстовые read_text/write_text тестов явно используют UTF-8; кодировка Windows
и Python runtime не меняются. AST guard ловит возвращение неявного encoding.
Свежая проверка этого комплекта: [HANDOFF_VALIDATION](docs/HANDOFF_VALIDATION.md).
Детальные контракты GUI/команд: [приёмка](docs/ACCEPTANCE_CHECKLIST.md).

## 1. Назначение и стек

Локальный голосовой ассистент для Windows, форк [jsys12/jarvis](https://github.com/jsys12/jarvis).
MIT и attribution оригинального автора сохраняются; см. `LICENSE`.
Основной запуск — Python 3.11.9 в `.venv311`; Windows-аудиостек с Vosk не переносить
на Python 3.13/3.14 без отдельной проверки совместимости DLL.

- GUI: Flet 1.0.x в главном потоке.
- STT: Vosk + faster-whisper; VAD: Silero ONNX.
- TTS: `auto` выбирает Silero → Piper → SAPI.
- LLM и эмбеддинги: Ollama, опционально; по умолчанию локальный адрес.
- Язык: `num2words` + `pymorphy3`, офлайн после установки зависимостей.
- Сборка: `scripts/build_exe.py` собирает лёгкий launcher, не автономный Python-runtime.
  `scripts/build_setup.py` + Inno Setup собирают установщик. Тег `v*` запускает release workflow.
- Погода и валюты используют сеть; первичная загрузка моделей/зависимостей тоже требует сети.
  Облачные TTS/LLM-провайдеры пока не реализованы.

## 2. Пути и пользовательские данные

```text
PROGRAM_DIR  C:\ProgramData\Phoenix    модели Vosk/Whisper и кэши, ASCII
USER_DIR     %APPDATA%\Phoenix         config, profiles, logs, timers, tasks
```

Все пути определяет `jarvis/paths.py`. Пользовательские пути могут содержать кириллицу;
модели Vosk обязаны находиться в ASCII-пути. `Path.home()` — только внутри `paths.py`.
`HF_HOME` на время загрузки Whisper восстанавливается в `finally`.
`paths.nonverbal_dir()` — read-only `assets/nonverbal/` рядом с пакетом
(либо в frozen resource root). Сэмплы не записываются в профиль.
`paths.temporary_audio_file()` создаёт временный WAV только для winsound-fallback
и удаляет его после остановки/окончания звука.

Личные `config.json`, `profiles/`, `dialog.json`, `system_caps.json`, пароли,
модели и артефакты сборки не коммитить и не включать в документацию/снимок.
Настройки-пример — только `config.example.json` без личных значений.

## 3. Поток обработки

```text
микрофон → VAD → Vosk (слова + conf) → извлечение обращения/окна диалога
  → PCM quality gate → Whisper (если включён) → проверка сегментов/расхождений
  → при сомнении: повторить; без исполнения и записи сомнительной расшифровки
  → IntentHandler.handle(raw text)
      ├─ pending_password: отдельная защищённая ветка до истории и коррекций
      ├─ language.analyze_command: числовые слоты + исходный текст
      ├─ normalize → pipeline
      └─ Reply(text | stream, allow_nonverbal=False по умолчанию)
  → Jarvis.say (_say_lock) → Speaker → TTS
      └─ PCM-движки: audio_output + необязательная Nonverbal-реакция
```

Pipeline, порядок важен:
`cancel → pending → onboarding → correction → password → memory → clipboard → modes → compound → clarification → fast → llm`.
Реестр `fast/`: специфичные правила выше общих; `custom` и `open_profile` не
перемещать ниже общих обработчиков. Ошибка одного обработчика логируется, не роняет цикл.
`mood.apply_from_text()` в `handle()` вызывается после разбора результата; просодия
применяется в голосовом `_process()` до обработчика. Не выдавать эвристику эмоций
или ASR-confidence за измеренную точность понимания.

## 4. Числа и неопределённость

- `jarvis/language/` — единый словарь/грамматика чисел, единиц и длительностей.
  `prepare_text()` использует его для TTS, включая контекстные римские цифры и падежи.
- Исходная фраза сохраняется отдельно от нормализованной команды. Не удалять
  пунктуацию/дробную запятую/двоеточие до семантического числового разбора.
- Меняются только распознанные командные слоты; произвольный текст задачи,
  пароли, имена и неоднозначные последовательности не исправляются догадками.
- `recognition.py`: PCM-проверка, Vosk word confidence, Whisper avg_logprob,
  no_speech_prob и compression_ratio; проверка каждого непустого сегмента.
- Низкая уверенность вызывает уточнение до GUI user-message, Observer и handler.
  Сильный Whisper может восстановить слабый Vosk; при ошибке Whisper fallback
  допустим только на достаточно уверенный Vosk. Числа/отрицания/поддержанные
  действия двух уверенных расшифровок сверяются дополнительно.
- Пороги `stt_min_word_confidence=0.65`, `stt_min_avg_logprob=-1.0`,
  `stt_max_no_speech_prob=0.6`, `stt_max_compression_ratio=2.4` — начальные,
  не откалиброванные под каждый микрофон вероятности.
- Parser `action=none` означает уточнение, не повторную попытку придумать команду.

### Уточнение незавершённой команды

`intents/clarification.py` расширяет существующий `_pending_question`, а не создаёт
новый менеджер: target приложения, время таймера, единицы длительности.
`PendingStage` стоит сразу после cancel; подтверждённый слот меняет `ctx.cmd`
и идёт дальше через password/custom/fast, без повторного применения fuzzy-коррекции.
`ClarificationStage` перед fast/LLM задаёт недостающий вопрос, сохраняя приоритет custom.
Ровно одно ожидание: monotonic-дедлайн 30 с, максимум три непонятных ответа;
срок не продлевается повторами. При новой поддержанной команде, отмене,
запросе пароля или смене профиля старое состояние очищается.
Таймер использует общую числовую грамматику; «на десять» требует единиц.
Текст напоминания сохраняется. Явная поправка до исполнения заменяет значение.
Изменение уже созданного таймера, произвольные слоты и автоматическое обучение —
не часть первого блока. Неизвестный ответ о приложении не угадывается как сайт.
Compound останавливается на вопросе/пароле; оставшиеся шаги не ставятся в очередь.
Короткие ответы в голосовом окне уточнения не передаются Observer как факты.
Существующий city_for_weather остаётся отдельным совместимым типом того же ожидания.

`_last_timings`: только handler_ms/stages_ms, без текста/паролей. Команда
«покажи время обработки» показывает предыдущий ход. Это время до возврата Reply,
не end-to-end latency: генерация stream после возврата, STT и TTS не входят.

## 5. Память и обучение

Источник фактов — `profile.json`, индекс `memory_index.json` производный и
восстанавливаемый. История диалога — отдельно, в `dialog.json`.
`memory_context.select_memory()` сначала определяет допустимые сведения по запросу.
`learning.build_context(query=...)` без запроса/релевантности не передаёт личные данные.
RAG (`memory_rag_enabled=false` по умолчанию) ищет только в разрешённых ключах.
Ошибка, пустой результат или малый набор фактов **не разрешают добавлять все факты**.
Общая просьба рассказать что-нибудь не получает имя, город, работу или предпочтения.

Коррекции применяются pipeline, а не становятся системными инструкциями для чата.
Observer выключен без согласия (`observer_enabled=false`); извлекает только прямые
утверждения пользователя. Ответы ассистента не источник фактов. Это сбор контекста,
а не тренировка весов LLM/ASR/TTS. Защитные фильтры не гарантируют безошибочную модель.

## 6. Non-verbal, этап 1.13.6

Реализованы четыре коротких CC0-реакции: laugh, sigh, hmm, yawn.
Происхождение и SHA-256 — `assets/nonverbal/sources.json`; пояснения — README рядом.
Выключатель во вкладке «Аудио» применяется сразу через общий Config.

- `nonverbal_enabled=false`, `nonverbal_cooldown_sec=45.0` (10–3600),
  `nonverbal_gain_db=-15.0` (−18…−12), `nonverbal_probability=0.2` (0–1).
- Только явное `Reply.allow_nonverbal=True` от диалогового ответа. Команды,
  пароль, таймеры и уточнения используют default false.
- Выбор по актуальному mood; mood уже учитывает prosody согласно её приоритету.
  happy/excited → laugh; neutral/bored → hmm; tired → sigh или yawn;
  annoyed/неизвестное состояние → без реакции. Это эвристика, не ML-классификатор.
- Максимум одна попытка на ответ, не на предложение; общий cooldown между ответами.
- `BaseEngine.set_wav_player()` направляет WAV из Silero/Piper в Speaker;
  `audio_output.py` декодирует/ресэмплирует/микширует PCM и выводит одним потоком.
- Уровень относительно RMS активной речи, ресэмплинг под частоту TTS, защита от
  клиппинга. Один stop-token обрывает речь и реакцию; реакция не создаёт второй плеер.
- Отсутствующий/повреждённый сэмпл оставляет обычную речь. SAPI — нативная озвучка
  без микширования. Кашель отложен, случайно изображать болезнь не требуется.
- Фиксированные записи не совпадают автоматически с тембром выбранного TTS.
  Windows-аудиоприёмка и прослушивание остаются ручными.

## 7. Неприкосновенные правила

1. Config — в памяти, чтение через `get`, запись через `Config.set`/`config_manager`;
   не читать/писать пользовательский JSON напрямую.
2. Запись пользовательских данных — атомарная, `mkstemp` + `os.replace`, FileLock
   per-path; учитывать PermissionError антивируса Windows.
3. Не заводить новые глобальные синглтоны. Политика реакций принадлежит Speaker;
   сессии хранят слабые ссылки, собственные блокировки и монотонное время.
4. Flet — главный поток, из фоновых потоков взаимодействовать через GUI-очередь.
5. `cmd_lock` сериализует GUI/голосовые команды; `_say_lock` — голос/таймеры/уведомления.
6. Vosk API только из listener-потока. `flush()` не трогает recognizer.
7. Per-call TTS stop-token; `wait_end()` возвращает bool. Не наслаивать новый поток
   при незавершённом старом. Barge-in не должен оставлять хвост реакции.
8. UIA — STA/COM и общий lock. Браузеры определяются через единый список и PID в `uia.py`.
   Ctrl+W fallback допустим только при непрочитанных вкладках, не при не найденном имени.
9. Опасность проверять до custom/pack-исполнения, включая все шаги макроса.
   Пароль — SHA-256 с префиксом + `hmac.compare_digest`; не логировать/запоминать ввод.
10. Ошибка записи задачи не превращается в «готово». ZIP — защита от Zip Slip.
11. Системные команды с аргументами — `_looks_like_cmd`/shlex/subprocess, не os.startfile.
12. Flet 1.x: `ft.Button`, не удалённые ElevatedButton/TextButton; COM/GUI/аудио проверять
    отдельно на Windows. `prevent_close` + `on_event` не считать рабочей связкой в 1.0.3.
13. PowerShell 5.1: не использовать `&&`; файлы — UTF-8 без BOM, CRLF.
14. Новые зависимости — только после согласования; числовые библиотеки уже согласованы.
15. Attribution jsys12 сохранять. Не коммитить личные данные, `.venv311`, models, voices,
    dist, build, logs, backups; CC0-активы поставляются с происхождением.

## 8. GUI: диалог и графитово-медная оболочка

Главная использует существующие Flet 1.0.x и очередь GUI. Состояния:
idle/listening/recognizing/thinking/speaking/awaiting/password/error.
recognizing и thinking получают сигналы из голосового пути; idle уточняется
по живому pending-состоянию. Это этапы обработки, не измерение точности/задержки.

- `_Sidebar` и нативные кнопки сценариев поддерживают клавиатуру; три карточки
  только заполняют поле, не исполняют действие и не меняют пароль.
- Режим, голос и объём истории — над композером. Тег модели — из Config,
  не проверка соединения. Нижний блок sidebar показывает текущий профиль.
- Брендовая медь отделена от функциональных/сигнальных цветов; знак птицы
  реагирует на состояние, без постоянной анимации и имитации аудиоданных.
- Enter отправляет, Shift+Enter добавляет строку. Пока GUI-запрос выполняется,
  следующая отправка блокируется без очереди; черновик остаётся редактируемым.
- Отдельный _command_lock защищает от повторных GUI-кликов; cmd_lock ядра
  по-прежнему сериализует голос и GUI. finally освобождает GUI-lock при ошибке.
- Стоп останавливает только текущую озвучку. Не отменяет HTTP/генерацию LLM,
  работу handler или уже выполненное системное действие; ожидание не снимается
  преждевременно. При незавершённой предыдущей озвучке новая GUI-команда не исполняется.
- _messages — модель отображения текущей GUI-сессии, не новая постоянная память.
  Пересборка темы/голосов перерисовывает сообщения и сохраняет активный стрим
  и обычный черновик; парольный черновик очищается, ввод пароля скрыт.
- Пользовательская прокрутка вверх отключает автоследование; обновление размеров
  списка само по себе его не отключает. Кнопка возвращает к последнему сообщению.
- Копирование через штатный Flet Clipboard; ошибка показывается, не скрывается.
- Ошибка worker отображается через очередь без сырого exception/пароля; повтор
  действия автоматически не запускается. Микрофон и его pause-состояние сохраняются.
- «Микрофон» и «Голос и звук» обновлены; «Персона» и «Настройки» также обновлены. Минимум native-окна остаётся 900×600.
  Браузерный Flet-стенд с отключёнными ОС/аудио не заменяет Windows-приёмку.

### Микрофон и голос

`gui_audio.py` — нативные карточки и SoundSettings, диагностические потоки
отдают только данные через GUI-очередь `sound_result`. Отдельных ASR/TTS/stream
нет. Состояние проверки сохраняется при смене темы/вкладки; повторный старт
блокируется до применения completion-события. Ошибки не содержат сырой payload.

Listener обновляет `level_updated_at` в callback по monotonic; GUI очищает
индикатор, если данным больше секунды. Тест собирает 3 с свежих current_rms,
не сбрасывает статистику; смена входа/Listener, pause/mute инвалидируют замер.
Шкала условная, не ASR-метрика; эмоция не выводится из session peak.
Проба голоса: фиксированный Reply без nonverbal → существующий Jarvis.say;
nonblocking `_command_lock` + cmd_lock, обычный _say_lock остаётся у ядра.
Pending password/question и текущая речь блокируют пробу без очереди/исполнения
handler. Stop остаётся остановкой речи; completion не доказывает физический звук.

### Минималистичная главная

`gui_home.py` — нативный HomeScreen (Flet), стартовый экран окна.
По умолчанию только локальные дата/время, фирменная птица, реальный статус
и темы. Нет композера или автоматического набора карточек. Опциональные
виджеты задач/быстрых действий описаны в разделе ниже; отдельные Планы — позже. В покое корона плавно
движется как декоративный элемент, не выдавая это за активность микрофона.
Центральная солнечная корона вынесена в `gui_home_fx.py`: нативный Canvas,
одна задача только на видимой Главной: 16 FPS в покое, до 24 FPS при активности.
Покой — одна медленная линия; слушание — две линии, ярче свечение и три
мягкие расходящиеся волны; речь — три плазменные линии и до 16 искр;
распознавание/обработка — более спокойное движение. Это декоративный эффект,
не анализ спектра и не синхронизация с фонемами TTS.
Режимы смешиваются по времени: нарастание около 0.8 с до 95%, спад около
1.5 с. Переход в середине другого продолжается из текущего смешанного
состояния. Скорость интегрируется в общую фазу, поэтому контуры не прыгают.
Уровень сигнала тоже сглажен (tau 0.30 с). Слои Canvas имеют постоянные
типы/порядок/число (35): дополнительные волны и искры появляются через
прозрачность, а не вставкой/удалением. Амплитуда бегущих волн усилена;
весь эффект остаётся в фиксированном Canvas 300×300. Во время затухания
сохраняется 24 FPS, после успокоения — 16 FPS. Входящий сигнал берётся
только из существующих current_rms/level_updated_at Listener (5 Гц, свежесть
не более секунды, без второго аудиопотока). Шум тоже может дать свечение.
Тишина, пауза, mute и устаревшие данные оставляют только фоновую корону,
но не включают усиленный эффект слушания. Короткий hold
350 мс сглаживает паузы. speaking имеет приоритет над входным уровнем.
При скрытии/сворачивании, смене вкладки, unmount/rebuild/stop задача гасится;
Config gui_motion_enabled и доступные системные reduce-motion flags
оставляют статичный рисунок. На кадре обновляется только Canvas.
mic_watchdog больше не произносит предупреждение о тишине и не переключает
вкладку: результат однократной проверки остаётся только в журнале.
Обработка настоящего сбоя аудиопотока и ручная диагностика не отключены.
«Диалог» остаётся отдельным экраном с прежним worker/stream/password-контрактом.
Внутренние ID 0..5 сохранены, HOME_TAB=6; NAV_ORDER показывает Главную первой.
Поэтому переходы из трея, audio/preferences и конструктора не переиндексируются.
Home отражает события состояния, не запускает модель/микрофон и не выдаёт
наличие выбранной модели за подключение. Если ядра нет — явная подпись.
Задача часов запускается только при mount, обновляет только date/clock при
смене минуты и отменяется при unmount/rebuild/stop; даты — на русском без
зависимости от локали ОС, время — локальное системное.
Смена темы сохраняет выбранную вкладку, обычный черновик и текущий стрим.
HTML-прототип в приложение не встроен. Новых runtime-зависимостей нет.

### Интерактивная боковая панель

`gui_sidebar.py` — нативные Button/Stack/Canvas Flet, без HTML/WebView.
Компактная ширина 76 px, раскрытая 252 px; при любой ширине окна
hover синхронно анимирует резерв контента за 200 мс (push). Панель не
перекрывает контент и на окнах уже 1100 px. Порога и зависимости от
on_size_change нет. Закрепление всегда выделяет панели место. Config хранит только явное закрепление
(`gui_sidebar_pinned`) и ручной флаг `gui_motion_enabled`; наведение не пишет диск.
Hover open 100 мс, close 320 мс, переход ширины 200 мс; icon scale 1.06.
Canvas рисует короткий медный сегмент по скруглённой рамке: один проход 850 мс,
не больше 30 кадров/с, затем очищается. Обновляется Canvas, а не вся страница.
Задачи ограничены и отменяются при уходе курсора, rebuild и unmount.
Системные disable_animations/reduce_motion читаются через SemanticsService;
если платформа их не предоставляет, доступен ручной флаг в Config.
Tab/focus раскрывает, Escape закрывает незакреплённую панель; mouse focus
не удерживает панель открытой. Список меню прокручивается отдельно от футера.
Hover использует смесь selected/card, активный пункт — selected; медь не
создаёт конкурирующей заливки. Выбранные темы и черновики не меняются.
Ручная приёмка Windows/DPI — отдельно от Linux/Flet-render тестов.

### Персона и общие настройки

`gui_preferences.py` — нативные Flet-контролы, общие карточки/поля/палитра,
ResponsiveRow с одной колонкой на узком окне и ScrollMode.AUTO.
Фон, карточки, поля, рамки и текст используют общую палитру P, как в
«Голосе и звуке»; медные акценты — общий P.brand. Отдельной палитры нет.
Выбранные темы: тёмная — «Сумерки» (04), светлая — «Тёплый фарфор» (05).
Общие токены также задают боковую панель, композер и пузырьки диалога.
Расположение и поведение не менялись. Без WebView,
параллельной памяти и дополнительных runtime-зависимостей.

Редактор хранит только временные черновики. Изменения контролов не записывают
данные до кнопки сохранения (кроме темы, у неё явное немедленное применение).
Набор текста обновляет только зависимые подписи, без обратной отправки value
редактируемого поля на каждый символ. Черновики сохраняются при смене темы/вкладки, но персона всегда привязана к
profile.current; при смене пользователя старый черновик не переносится.
`profile.read_fields/update_fields` используют общий profile lock, идентификатор
и исходные значения; name/persona сохраняются одним config_manager.save.
Факты, история, onboarding и неизвестные поля persona сохраняются. Сброс
знакомства подтверждается отдельно. Глобальный Config.name не используется
новым редактором и не мигрируется молча. Портрет/цитата — явный пример стиля,
не генерация, не запуск команды и не обучение.

Общие настройки сохраняют только изменённые ключи одним Config.update с
expected_values. Config.set/update сериализованы RLock, не публикуют данные
до успешного сохранения; уведомления идут после записи вне write-lock.
Конфликт/ошибка сохраняют черновик. Тема — сразу, модель/трей/RAG — после
Применить, Observer и launch_mode — после перезапуска. Запуск tray при
выключенном трее запрещён; смена модели/адреса блокируется во время GUI-команды.

Проверка Ollama запускается только кнопкой: один worker → `preferences_result`
в штатной GUI-очереди. GET /api/tags, timeout 4 с на socket-операцию, ответ до
1 MiB; без генерации, pull, прокси окружения, редиректов и credentials в URL.
Ответы/исключения не показываются сырым текстом; поколения отсеивают устаревшие
результаты. Это наличие моделей, не проверка качества/реальной генерации.
Включение RAG или смена его сервера требует найденного configured embedding-тега.
Путь/тег модели и удалённый URL не выдаются за подтверждение приватности.

### Конструктор «Мои команды»

`command_builder.py` — чистая валидация/CRUD существующего custom_commands;
`gui_commands.py` — Flet-редактор без исполнения. Поддержан builder_version=1,
стабильный id, enabled, exact, 1–12 фраз и 1–6 типизированных шагов.
Legacy-записи остаются неизменными и read-only в GUI; паки не дублируются.
`IntentHandler._on_config_change` перечитывает custom_commands/active_packs,
публикуя новый список; находящийся в ожидании пароля сценарий хранит свой snapshot.
Выключение/перезагрузка — типизированный фиксированный argv, не shell-строка;
требуют настроенного пароля и preflight всех шагов. Параметры фиксированы.
`find_custom` — без исполнения, сначала точные совпадения, затем legacy fuzzy.
Значки: SVG/PNG в `jarvis/assets/brand`, общий знак для Flet/icon.ico/tray.png;
`make_icon.py` воспроизводит ICO/трей из PNG-мастера. Новых зависимостей нет.

## 9. Проверки и выпуск

```powershell
.\.venv311\Scripts\python.exe check_all.py
.\.venv311\Scripts\python.exe snapshot.py
.\.venv311\Scripts\python.exe snapshot.py --check
```

`check_all.py`: синтаксис → pytest → `test_intents.py` → `stress_intents.py`.
Интенты: 41 сценарий, 34 без LLM/сети; стресс: 102. Число pytest зависит от
доступных библиотек и платформы; актуальные результаты/ограничения — `tests/README.md`.
CI дополнительно проверяет snapshot. Зелёный ограниченный Linux-прогон не заменяет
Windows CI, живой микрофон, COM, установщик и прослушивание.

Перед коммитом обновить изменённые руководства и затем сгенерировать SNAPSHOT.md
тем же коммитом. README — витрина проекта: заголовок, бейджи, описание и оглавление
не закрывать блоками обновлений. Датированные изменения — в CHANGELOG, описание
возможностей — в README и docs/USER_GUIDE.md.
README — краткий запуск и навигация; docs/USER_GUIDE.md — подробные настройки,
диагностика и ограничения; assets/readme/hero*.svg — статичные обложки, не скриншоты GUI. Старые записи CHANGELOG и graphify-отчёт — история, не текущая карта.

### Локальная проверка подготовленного коммита

Одноразово: `python scripts/install_git_hooks.py`. Установка добровольная, только
одного `.git/hooks/pre-commit`; существующий hook и core.hooksPath сохраняются,
при конфликте установка отказывается и предлагает ручную интеграцию.
`scripts/check_staged_snapshot.py` читает индекс Git и проверяет staged-версию
snapshot.py/SNAPSHOT.md на временном дереве только подготовленных файлов.
Не делает git add/commit/push, не переписывает рабочие файлы или индекс. Частичный
staging учитывается: свежий рабочий SNAPSHOT не маскирует старый в индексе.
Конфликт индекса/симлинк входного файла/нет снимка — отказ, не успешный пропуск.
`pytest-log.txt` исключён из Git/Cline/snapshot; уже tracked-файл нужно отдельно
убрать из индекса через git rm --cached, не удаляя локально. См. CONTRIBUTING.md.

### Отдельная аудиорегрессия

`scripts/audio_regression.py prepare` синтезирует версионированный корпус;
`run` использует локальные модели, file-mode Listener и настоящий `_process`.
`tests/audio/` содержит схемы, сборку корпуса, безопасный ограниченный harness
и отчёты; `test_audio_regression.py` проверяет их контракты без моделей.
Не импортировать аудиопакет из runtime-приложения. Для replay не нужен PortAudio;
для микрофона `Listener` по-прежнему явно требует sounddevice/PortAudio и Vosk.
`WhisperTranscriber(local_files_only=True)` запрещает догрузку модели раннером.
В обычном приложении этот параметр по умолчанию False, поведение загрузки сохранено.
WAV/отчёты: `paths.audio_regression_dir()` → USER_DIR/audio-regression.
См. tests/audio/README.md: покрытие ограничено open/timer/cancel, это не весь реестр.

## 10. Направление развития

Цель — максимальная реализация видения JASTIN от работодателя, с обоснованными
оговорками и согласованием изменений. Этапы R0–R6 в PLAN.md; полный переход —
docs/PHOENIX_JASTIN_RECONCILIATION.md. Сначала рабочая аудиобаза и потоковый TTS,
затем модульность/skills, consensus/Trust, защищённая память и обучение,
целевые SDK/сценарии/UI/router/TTS, поставка. Это план, не готовые функции.
Vosk сейчас не удаляется, целевой wake/fallback сохраняется. Не фиксировать
Flet/JSON/Ollama-only как вечные ограничения против целевого документа.
Non-verbal/микрофон/установщик по-прежнему требуют ручной Windows-приёмки.
