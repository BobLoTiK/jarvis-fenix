## 🎯 Курс: сначала сам Феникс

Развиваем понимание, предсказуемость, локальную память, скорость и стабильность.
Облако, Telegram/веб, Hermes, MCP, плагины, VLM и подобные расширения убраны
из активной очереди. Новая интеграция не заменяет улучшение ядра.

- Один законченный шаг за раз, без переписывания работающего стека.
- Сначала измеряем узкое место, затем оптимизируем; ускорение подтверждаем замером.
- Переиспользуем pipeline, числовую грамматику, ASR-gate и существующее обучение.
- Vosk сохраняем. Его удаление/замена и сравнение альтернатив не входят в план;
  улучшаем существующий VAD → Vosk → опциональный Whisper, не ослабляя проверки.
- Без новых тяжёлых зависимостей и без скрытой отправки данных наружу.
- Смена локальной LLM не должна обнулять память и навыки самого приложения.
- Веса модели сами от разговоров не меняются. Самообучение приложения и LoRA — разные задачи.

## А. 🚧 Уточнения и незавершённая команда — реализовано, приёмка Windows

Цель: недостающий параметр не превращается в догадку или свободный чат.

### Реализовано в первом ограниченном наборе

- Одно ожидание в существующем `handler._pending_question`, без второго менеджера.
- «Открой» → вопрос о приложении → точное известное имя/алиас/ярлык/Steam-игра.
  Непонятный ответ не превращается в предположение о сайте. Полные команды открытия
  продолжают работать через прежние обработчики; это не новая политика всех open-команд.
- «Поставь таймер» → вопрос о времени → существующий исполнитель таймеров.
- «Напомни выпить чай» → вопрос о времени, текст напоминания сохраняется.
- «На десять» → запрос единиц → «минут»; минуты не выбираются молча.
- Явное исправление времени/цели ДО исполнения: «на десять… нет, на пятнадцать минут».
- Отмена, фиксированный монотонный срок 30 с, максимум три непонятых ответа.
- Поддержанная новая команда заменяет ожидание; смена профиля очищает временное состояние.
- В составной команде выполнение останавливается на недостающем слоте/пароле.
  Остаток составной команды не сохраняется для автоматического продолжения.
- Результат уточнения возвращается в обычный pipeline, не обходит пароль/custom.
- Голосовые ответы на ожидаемый слот не идут в Observer как постоянные факты.
- Замер handler/stages через perf_counter, без текста/паролей в метриках.
  «Покажи время обработки» — предыдущий ход, без STT, генерации стрима и TTS.

   при нескольких кандидатах переспросить. Не создавать второй по догадке.
4. Расширять схемы слотов только под реальные сценарии; один валидатор и один путь исполнения.
5. Любое подтверждение привязать к действию/профилю/сроку; не выполнять устаревшее «да».

Готовность: согласованный набор многоходовых сценариев и проверки отмены/отказа,
без регрессии обычных команд и без зависимости от одной локальной LLM.

## В. ⏭ Управляемое самообучение приложения

Основа — существующие `learning.py`, `profile.py`, коррекции и RAG, не параллельная память.

- Пользователь исправил смысл → Феникс предлагает запомнить → явное подтверждение.
- Запись: исходная формулировка, проверенное значение/действие, источник,
  область применения, профиль и версия схемы.
- Просмотр, удаление и откат; ошибки записи не озвучиваются как успех.
- Учитывать отрицания, параметры и контекст; similarity сам по себе не разрешение действовать.
- Не учиться на собственных ответах, сомнительной ASR или молчании пользователя.
- Никакие выученные связи не снимают пароль/подтверждения опасных действий.
- Проверенные записи сохраняются при смене локальной модели.

Этот этап ещё НЕ реализован новым механизмом уточнений. Существующие команды
памяти/коррекции остаются, но не объявляются готовым подтверждаемым самообучением.

## Г. ⏭ Качество памяти и разговора

- Проверить факты против временных состояний, конфликты и актуальность.
- Не ссылаться на запись без необходимости; отвечать по текущему вопросу.
- Контекст темы и краткое резюме длинного разговора — только с критериями качества.
- Проверить RAG с реальной локальной embedding-моделью, не только mocks.

## Д. P1 / M3 — Производительность по измерениям после GUI

Начальный handler-замер уже есть, полный путь предстоит инструментировать:

1. конец речи → STT;
2. готовый текст → разбор/выполнение;
3. локальная LLM → первый фрагмент ответа;
4. текст → начало слышимой речи;
5. холодный/тёплый запуск, CPU/RAM в ожидании и под нагрузкой.

Фиксировать модель, настройки, железо и холодный/тёплый режим локально.
Сравнивать медиану и p95 одинаковых сценариев. Не публиковать личные данные.
Целевые бюджеты назначать ПОСЛЕ исходных замеров, не выдумывать миллисекунды.
Оптимизировать измеренные повторные вычисления/загрузки, блокировки и ненужные LLM-вызовы.

## Е. Сквозная проверка качества и стабильности

- Пополнять набор сценариев после подтверждённых реальных ошибок.
- Сценарии: обычная речь, шум, оговорки, отрицания, числа, отмена и исправления.
- Проверять не только правильные действия, но и правильные отказы/вопросы.
- Записи голоса — только по согласию, локально; не складывать их в репозиторий.
- Чистая Windows: пути, зависимости, первый запуск, обновление и assets.
- Ручная приёмка Non-verbal/микрофона/COM/установщика остаётся частью качества,
  но не требует сначала строить облако или внешние интеграции.
