# Феникс — задание для нового чата

Работаем с существующим Windows-ассистентом «Феникс».
**JASTIN — целевое видение реализации Феникса от работодателя**, не сторонний
проект для выборочного заимствования. Нужно стремиться к нему максимально,
с небольшими техническими/безопасностными оговорками. Требования не вычёркивать
самостоятельно; спорные изменения и выбор технологий согласовывать.

## Сначала прочитай

AGENTS.md → PROJECT.md → PLAN.md → docs/NEXT_STEPS.md.
Далее только нужные исходники и тесты. Целевая матрица —
docs/PHOENIX_JASTIN_RECONCILIATION.md; оригиналы — docs/reference/.
Свежие результаты — docs/HANDOFF_VALIDATION.md. Предыдущая переписка не нужна.
SNAPSHOT — дополнительный переносимый снимок, не первый файл для чтения целиком.

## Что есть

Windows x64, Python 3.11.9; Flet; Silero VAD/Vosk/опциональный faster-whisper;
Ollama; auto TTS Silero → Piper → SAPI. WinRT TTS удалён, WinRT Media Control
оставлен. Профили/история/индекс пока JSON. Команды — существующий typed pipeline
и редактор статических шагов. Есть speak_stream, но новый bounded pipeline
с доказанным перекрытием генерации/синтеза/воспроизведения ещё не сделан.

Целевые voice_core/Event Bus/SDK, Sherpa/GigaAM/fastText, ECAPA/consensus/Trust,
SQLCipher/DPAPI, сценарии/Litegraph, GUI/dock, provider router и новые TTS —
этапы R2–R6, а не уже готовые возможности. Flet/Vosk/Ollama — рабочая база,
не запрет на целевое развитие. Vosk как минимум wake/fallback сохраняется.

## Текущий статус

AEC через колонки улучшился, но оставались самоперебивания. «Х» в «их» —
подозреваемый сценарий, причина ещё не доказана. Последний подготовленный пакет
no-WinRT/диагностики пользователь пока не проверял. Не объявлять установленным.
Обычный AEC — Piper; ручная PCM/AEC-диагностика Piper/Silero;
SAPI без PCM — только метаданные. Render timing оценочный, не DAC/ADC sync.
Проверки Windows-аудио/Setup пользователь отложил, перед релизом они обязательны.

## Ближайшая инженерная задача

1. Проверить tts.py, tts_engines/, audio_output.py, main.py, brain.py, safety.py
   и stream/cancel tests. Зафиксировать, где генератор блокируется на синтезе/звуке.
2. Подготовить baseline: первый chunk → безопасная фраза → PCM → слышимый старт;
   паузы, cold/warm median/p95, CPU/RAM, отмена. Не выдумывать замеры без Windows.
3. Предложить один минимальный bounded streaming патч. В следующем шаге —
   реализация и тесты, не строительство всего JASTIN одновременно.
4. Если нужны пользовательские записи/Windows-доступ, запросить именно их.
   Отсутствие приёмки не блокирует анализ/тесты, но блокирует заявление «принято».

Не ждать всего LLM-ответа до озвучки. Маленькая ограниченная очередь,
backpressure/порядок; Stop отменяет текущий ответ и всю непроговорённую очередь.
Короткий de-click хвост только активного PCM, один итоговый output/AEC block.
Длина по измерениям, не обязательные 200–300 мс; нет доигрывания накопленных фраз.
Fade не лечит ложный barge-in. Жёсткая отмена/выход не должны зависать.
Silero rate требует проверки фактического применения; не менять sample rate/pitch
как замену реализации темпа. Не менять голос, auto или модель Ollama молча.

## Не сломать

Safety/finalize_stream/историю, ASR gate, pending password/question, cmd_lock,
_say_lock, per-call token и владельцев GUI/Vosk/UIA. Один PCM/микрофон/плеер.
Данные/настройки атомарно и profile-scoped, поздний callback не пишет в новый
профиль. Ошибка/timeout не становятся успехом. Нет скрытой отправки данных.

## Как закончить шаг

Один законченный срез с регрессиями; обновить документы и snapshot, проверить
архив на копии. Назвать точные команды/платформу/пропуски. Linux/mocks не
заменяют Windows-аудио, COM, GUI, установщик. Не обещать готовую Nuitka/EXE
сборку, новую модель или пройденную приёмку без фактического результата.
Если новой задачи нет — кратко подтверди понимание и начни с аудита указанного
LLM/TTS пути; не начинай без согласования UI-миграцию, облако или биометрию.
