# AEC Piper: экспериментальный прототип

Цель — проверить эхоподавление при голосе Феникса через колонки, не менять
ASR и не делать установку виртуального драйвера обязательной. Проверка Setup
по просьбе пользователя пока отложена. Этот документ не подтверждает чистую
установку или устранение эха на Windows.

## Включить без команд в PowerShell

1. Полностью выйди из Феникса, включая трей. Закрытие окна может лишь свернуть
   его в трей. Сохрани свои изменения исходников отдельно, затем замени файлы
   архива в корне проекта: рядом с launcher.py должны быть install_aec.bat и jarvis.
2. Дважды нажми **install_aec.bat**. Он спрашивает подтверждение клавишей,
   использует только локальную .venv311 и pip --only-binary=:all: с
   requirements-aec.txt (pywebrtc-audio==0.2.0). Не запускает компилятор,
   не устанавливает драйвер и не скачивает модели. Интернет/PyPI нужны только
   для установки. После установки отдельно проверяется создание native processor.
   Ошибку DLL/импорта не обходи: сохрани текст; оставь эксперимент выключенным.
3. Открой Феникс обычным способом. В **Голос и звук** выбери **Piper**.
   В «Распознавание и фильтр тишины» включи **AEC: эхо колонок — Piper,
   эксперимент (после перезапуска)**. Затем полностью выйди через трей и запусти снова.

Голос Piper должен быть подготовлен; пакет AEC его не скачивает и не выбирает.
Auto-порядок TTS остаётся Silero → Piper → WinRT → SAPI, без молчаливой смены.
Одного установленного wheel недостаточно: флаг и выбранный Piper нужны отдельно.
Для отключения сними флаг и полностью перезапусти приложение. Удалять wheel
не требуется. Базовый requirements.txt не включает optional AEC.

Изменения AEC — Python-исходники, отдельная перекомпиляция EXE ради AEC не нужна.
Если также применяются прежние изменения frozen launcher, они по-прежнему требуют
будущей пересборки EXE/Setup; текущая проверка AEC этого не заменяет.

## Реализация

- jarvis/echo.py: один daemon capture worker владеет AudioProcessor. Импорт,
  native init, reset и process не выполняются в PortAudio callback. Startup
  не ждёт native init: пока он не готов, используется прежний путь.
- Только mic **16000 Гц**. В opt-in режиме capture block **2560 samples / 160 мс**:
  кратен 160 (10 мс WebRTC) и 512 (Silero VAD). Это предотвращает искусственное
  дописывание нулей между блоками wrapper и потерю хвоста VAD. Default off
  сохраняет прежние 2048 / 128 мс. Даже при отказе optional backend запрошенный
  opt-in stream остаётся 160 мс до перезапуска с выключенным флагом.
- Render reference — PCM Piper после nonverbal mixing, небольшими фрагментами
  непосредственно перед stream.write. Копируется только mono reference; stereo
  приводится усреднением (штатный Piper — mono). Rate согласуется интерполяцией
  по времени, это не отдельный проигрыватель.
- Время воспроизведения оценивается из monotonic clock, OutputStream.latency и
  последовательности write. Mic ADC time переводится через PortAudio time_info.
  Это **не измерение фактического DAC, не WASAPI loopback и не устранение clock drift**.
  Stream delay hint aec_stream_delay_ms (default40, clamp0..500) — настройка
  для эксперимента, не универсальная калибровка. При плохой синхронизации AEC
  может работать слабо/не помогать; именно это надо проверить на Windows.
- Processor: AEC3; NS и AGC намеренно выключены, чтобы не менять усиление/VAD
  одновременно. Capture PCM → AEC → прежний VAD и recognizer. Для AEC barge-in:
  native speech probability >=0.6, очищенный RMS >=150 и VAD (если включён),
  накопленная речь >=150мс. При 160мс блоках это не обещание мгновенного stop.
  Speech probability не идентифицирует человека и сама не доказывает отсутствие эха.
- Physical mic meter/watchdog сохраняет raw RMS, чтобы подавленное эхо не выдать
  за отключённый микрофон. ASR/Whisper получают очищенные байты и прежний gate.
- В RAM: не более4 capture блоков, reference deque <=80 маленьких блоков с
  удалением старше2сек, pre-roll <=3 cleaned блоков (480мс). Capture старше300мс
  не догоняет UI бесконечно. Аудио не пишется на диск и не логируется.
- При overflow/разрыве/ошибке stale epoch не возвращается в ASR. Sentinel
  очищает распознаватель **в его собственном потоке**, не из callback/DSP/GUI.
  При AEC barge-in очищенный pre-roll сохраняет начало пользователя через
  штатный stop/flush. Это нуждается в живой проверке: идеальный onset не обещан.
- Смена микрофона/разрыв сбрасывает reference/DSP; до нового Piper PCM reference
  может временно отсутствовать. Старое render_end не закрывает новый render.
- Все источники продолжают использовать прежний per-call token и общий PCM;
  safety, finalize_stream, history, cmd_lock/_say_lock и чтение LLM по фразам
  не переписаны. Нет ожидания всего LLM-ответа и второго конвейера команд.

## Ограничения и fallback

Только **Piper + sounddevice PCM**. Для Silero/WinRT/SAPI и winsound fallback
в этом прототипе нет гарантированного reference; остаётся прежнее поведение.
Piper idle/reverb tail обрабатываются без записи всего системного звука.
Нет виртуальных кабелей, WASAPI loopback, автоустановки, скрытого скачивания,
изменения выбора голоса или настройки Windows. Native ImportError/OSError и
Python processing exception переводят путь в fallback. Нативный access violation
не может быть надёжно пойман обычным Python try/except; Windows-приёмка обязательна.

Пока не добавлены fade-out, новый TTS-буфер, автоматическая калибровка задержки,
системное эхоподавление всех приложений и поддержка всех движков.
Гонка событий Диалога и падение самой Sandbox отдельно этим не исправлены.

## Проверка через реальные колонки — ещё не выполнена

Sandbox не годится как единственное подтверждение акустики: там другое
перенаправление устройств, а у пользователя она уже падала. Проверяй на основной
Windows обычным установленным кодом проекта, без чужих EXE/драйверов; AEC легко
выключить. Не путать это с проверкой неизвестного DOCX: она отдельная задача.

1. Выбран физический микрофон, не Stereo Mix/виртуальный вход. Начни с умеренной
   громкости. В jarvis.log ищи строку AEC: Piper PCM, WebRTC AEC3 готов.
2. Феникс произносит ответ через колонки, ты молчишь: не должен сам перебиваться
   и выполнять собственную речь. Сравни on/off при одинаковой громкости/расположении.
3. Во время ответа скажи новую команду с обращением; проверь stop и целую фразу,
   особенно начало. Повтори тихо/обычно, в начале/середине/конце ответа.
4. Проверь Stop в GUI, следующую текстовую команду, выход/повторный запуск,
   смену микрофона, отказ optional пакета и выключение AEC.
5. Если эхо осталось/слова теряются — сообщи конкретный сценарий и ошибки AEC
   из лога. Не включай AGC/NS/драйверы одновременно и не считай факт запуска
   доказательством хорошего эхоподавления.

Не надо присылать личный config/profile или полные записи разговоров.
