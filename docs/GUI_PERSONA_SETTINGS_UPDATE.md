# Обновление «Персона и Настройки»

Для исходного проекта из jarvis.zip. Это **архив изменённых исходников**, не
автономный установщик и не новая exe-сборка. Новых runtime-зависимостей нет.
Flet 1.0.3/1.0.4; целевой запуск остаётся Windows / Python 3.11.9 / .venv311.

## Установка

1. Полностью завершите Феникс, включая процесс в трее. Закрыть окно недостаточно.
2. Сделайте резервную копию папки проекта или сохраните текущие изменения в Git.
3. Распакуйте содержимое обновления **в корень существующего проекта**, где
   лежат launcher.py, PLAN.md и папка jarvis. Согласитесь на замену файлов.
   Путь внутри ZIP `jarvis/gui.py` должен стать `<проект>\jarvis\gui.py`,
   а не `<проект>\jarvis\jarvis\gui.py`.
4. В PowerShell, находясь в корне проекта, выполните:

```powershell
.\.venv311\Scripts\python.exe -m pytest tests/test_gui_preferences.py tests/test_gui_wiring.py tests/test_gui_chat.py tests/test_gui_audio.py tests/test_gui_commands.py -q
.\.venv311\Scripts\python.exe check_all.py
.\.venv311\Scripts\python.exe snapshot.py --check
.\.venv311\Scripts\python.exe -m jarvis
```

Не используйте случайный системный Python 3.13/3.14 для Windows/Vosk-runtime.
Архив не содержит config.json, профили, пароли, историю, модели, .venv или exe.
Эти данные не заменяются. Vosk, ASR gate, TTS и pipeline не переписаны.
Сохранение из самих новых экранов, разумеется, меняет выбранные вами параметры.

## Что изменилось

- Персона: текущие имена, стиль/тон, чипы черт, контекст и пример манеры без LLM.
- Имя и persona сохраняются одним пакетом текущего профиля. Глобальное поле
  Config.name больше не источник имени в этом экране; скрытой миграции нет.
- Изменения применяются кнопкой; черновики остаются при смене темы/вкладки.
  При смене профиля старый черновик персоны не переносится другому пользователю.
- Ошибки/конфликты не выдаются за успех. Повторное знакомство требует подтверждения
  и не удаляет факты/историю. Отмена черновика загружает актуальные данные.
- Настройки: модель/URL, приватность, тема, трей и режим запуска. Голос/темп —
  только в «Голосе и звуке», без дублирующих контролов.
- Тема применяется сразу; остальные поля — кнопкой. Observer и launch_mode
  требуют перезапуска, что прямо написано рядом с контролами.
- «Проверить подключение» читает /api/tags выбранной Ollama. Не запускает генерацию,
  не скачивает моделей. При удалённом адресе данные идут выбранному серверу.
  Включение RAG через экран требует найденной embedding-модели.
- Новый адрес уведомляется раньше смены модели, чтобы существующий Brain warmup
  не отправлялся на старый сервер. Само поведение warmup ядра не переписано.

## Что проверить на вашей Windows

- Два экрана в тёмной/светлой теме, 900×600 и DPI 100/125/150%.
- Быстрый ввод, Enter при добавлении черты, многострочный контекст, смена стиля.
- Сохранение, отмена, ошибка записи; смена профиля не переносит чужой черновик.
- Тема во время несохранённых изменений, переходы в Диалог/Голос и обратно.
- Живая Ollama: корректный/неверный адрес, сервер недоступен, модель отсутствует;
  проверка — это только наличие тегов, не гарантия генерации.
- Включение и отключение Observer после перезапуска; RAG с реальными embeddings.
- Трей, выключение трея, режим запуска и отсутствие спрятанного окна без трея.

Проверки разработки: Linux/Python 3.13; 993 passed / 5 skipped в переносимом
наборе, 161 passed в GUI-наборе также на Flet 1.0.3. Подробные ограничения —
в tests/README.md. Windows CI, полный Windows check_all, живой звук и установщик
здесь не запускались; эти пункты не объявлены принятыми.
