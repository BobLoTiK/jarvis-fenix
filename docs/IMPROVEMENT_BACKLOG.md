# Улучшения после сравнения пяти ассистентов

Статус: план, не реализованные функции. Анализ README и отдельных исходников,
без запуска конкурентов и без сравнительных замеров производительности.
Основной порядок: запуск → голосовой конвейер → быстрые команды → UX → новые функции.

**JASTIN — целевое видение Феникса от работодателя**, не ещё один конкурент.
Этот старый тематический бэклог дополняет маршрут, но не ограничивает его.
[Путь к JASTIN](PHOENIX_JASTIN_RECONCILIATION.md),
[PLAN](../PLAN.md), [NEXT_STEPS](NEXT_STEPS.md) — актуальные цель/очередь.
Setup-приёмка отложена, аудиоприёмка не завершена. Биометрия, SDK, защищённая
память, сценарии, UI/dock и router включены в маршрут, а не исключены из цели.

## P0. Установка и запуск — релизный gate, приёмка отложена

- [ ] Получить launcher.log с компьютера, где ярлык не открывает приложение.
      Причина пользовательского сбоя пока не установлена; не объявлять исправленной.
- [ ] Перестать считать успешный Popen подтверждением запуска GUI.
      Различать создание процесса, готовность сессии GUI/режима трея,
      раннее завершение и таймаут без принудительного убийства процесса.
- [ ] Сохранять ранние stderr/import/native-ошибки до настройки runtime-логирования.
      Показывать путь к журналу в существующем окне подготовки, без цепочки модалок.
- [ ] Проверить влияние временных DLL/Tcl/Python-путей PyInstaller на дочерний
      Python. Исправление касается только дочернего запуска, не системной среды.
- [ ] Не превращать исключение создания GUI в молчаливый headless-режим.
- [ ] Проверить доступность папки журналов при установке в другую/readonly-папку.
- [ ] Сохранить вывод pip и dependency probe при ошибке, не только код возврата.
- [ ] Добавить регрессии: ранний exit, отказ Popen, готовый GUI, tray/headless,
      существующий экземпляр, устаревшее подтверждение, таймаут, повтор после ошибки.
- [ ] Пересобрать launcher EXE и Setup на Windows; замена .py не обновляет старый EXE.
- [ ] Windows smoke: чистая установка и обновление, путь с пробелами/кириллицей,
      обычный пользователь, GUI/tray, повторный запуск, отсутствие лишнего Flet-shell.

Критерий: пользователь либо видит выбранный интерфейс, либо получает объяснение
с точным путём к журналу. Linux/mocks не заменяют Windows-проверку.
Не менять Python 3.11/Flet/runtime-зависимости без отдельного решения.

## P1. Отзывчивая локальная озвучка вместе с Ollama

- [ ] Baseline: первый LLM chunk, безопасная фраза, PCM, первый звук, паузы,
      CPU/RAM и отмена на нескольких конфигурациях Windows.
- [ ] Перекрыть генерацию текста, синтез и проигрывание: маленькие ограниченные
      очереди, backpressure, порядок фраз, один активный плеер.
- [ ] Надёжный stop/barge-in: отменить остаток и фоновые задачи текущего ответа.
- [ ] Лёгкий пакет Piper: явные модель/размер/лицензия, один активный голос,
      контроль CPU-потоков, fallback без скрытых загрузок и предположений о GPU.
- [ ] Ограничить конкуренцию TTS/STT/Ollama за ресурсы; не резервировать все ядра.
- [ ] Проверить реальное применение Silero rate без изменения высоты голоса.
- [ ] Словарь произношения: имена, бренды, аббревиатуры, проверяемая нормализация
      чисел/дат/единиц с переиспользованием существующего language-модуля.
- [ ] Sherpa-ONNX рассматривать только как отдельный кандидат TTS после baseline
      и согласования зависимости. Vosk не заменять, не начинать новый ASR A/B.

Ориентиры: NikkyWay/jarvis — раздельные synth/play workers, но его неограниченную
очередь текста и секундный XTTS prebuffer не копировать. Mike — CPU/NumThreads.
Обязательное ожидание полного ответа, клонирование/обучение голоса и облако отложены.
Нулевую нагрузку и скорость чужих моделей на любых компьютерах не обещать.

## P1/P2. Быстрые команды и меньше ложных активаций

- [ ] Аудит существующих fast-правил Phoenix: простые команды обходят Ollama;
      сначала тесты/замеры, не создавать параллельный конкурирующий pipeline.
- [ ] Расширить варианты фраз и извлечение слотов; малая ONNX NLU — лишь кандидат,
      если доказана польза относительно действующих правил (идея Akira).
- [ ] Сверить существующий ASR-gate с различением обращения/упоминания имени
      (идея NikkyWay). Сначала дешёвые локальные проверки, без облачного gate.
- [ ] Сохранять confidence/уточнение, safety и проверку опасности до исполнения.

## P2. Удобство для обычного пользователя

- [ ] Мастер первого запуска: микрофон → проба голоса → Ollama, с возможностью
      пропуска необязательных шагов и понятным статусом компонентов.
- [ ] Разделить базовую поставку и тяжёлые компоненты на явные пакеты;
      сетевые функции/размеры загрузок/лицензии обозначать заранее.
- [ ] Развивать существующий редактор «Мои команды»: фраза → типизированные
      действия → проверка → сохранение, последовательности с понятными ошибками.
      Ориентир Alpha: UX сценариев, не eval/os.system как общий диспетчер.
- [ ] Произвольные скрипты не включать в обычные действия без отдельного
      согласования расширенного режима и модели безопасности.
- [ ] Сохранить минимальную Главную, необязательные виджеты и выдвижную панель,
      которая отодвигает контент. Не переписывать Flet ради чужого интерфейса.

## P2. Практичные инструменты после стабилизации

- [ ] Индекс только выбранных пользователем папок: обновление/отмена/лимиты,
      несколько найденных результатов и выбор, никаких сканирований LAN по умолчанию.
- [ ] Outlook: поиск контакта, предпросмотр и создание черновика; отправка письма
      не разрешена одним фактом генерации текста моделью (идея alpha_ai_agent).
- [ ] Агентные шаги ограничены, системная инструкция не теряется при обрезке
      истории, инструменты типизированы. Простой запуск не требует серии LLM-запросов.
- [ ] Диагностический отчёт только по запросу, без секретов/истории/записей речи.
