# Проверка комплекта передачи Феникса

## Что это за комплект

Полные текущие исходники/тесты/ресурсы, чистые стартовые документы и три
оригинала требований. Подходит для продолжения в новом чате без переписки.
Это не опубликованный релиз, EXE/Setup или подтверждение стабильности на Windows.
Аудио/GUI/LLM runtime, requirements и настройки не менялись. Усилен snapshot.py
и добавлены проверки dotenv, необязательных DOCX, холодных импортов и явного
UTF-8 в тестовых read_text/write_text. Кодировка системы не меняется.
Старт: START_HERE → AGENTS/PROJECT/PLAN → PROMPT/NEXT_STEPS.

## Свежая переносимая проверка

Среда: Linux, Python 3.13.14, отдельный venv вне проекта,
requirements-ci.txt; Flet 1.0.5, pytest 9.1.1, numpy 2.5.4.
Это не целевая Windows/Python 3.11.9 и не версия зависимостей пользователя.

```bash
PYSTRAY_BACKEND=dummy python -m pytest tests/ -q -rs \
  --ignore=tests/test_browser_target.py \
  --ignore=tests/test_window_targets.py
```

**1520 passed, 9 skipped, 148 warnings.** Полные логи сохранены вне исходников,
не включены в архив. Числа не сравнивать напрямую с прогонами на другом наборе
optional-зависимостей. Предупреждения относятся к deprecated Flet InputBorder.NONE;
эта зависимостная миграция не выполнялась попутно со стабилизацией документов.

### Что не выполнялось в этом наборе

- Два файла исключены на Linux: test_browser_target.py/test_window_targets.py
  требуют Windows winreg. На целевой Windows их не исключать.
- Пропущены проверки main wiring/STT при отсутствии vosk/sounddevice,
  tray при отсутствии pystray, VAD/реального ONNX при отсутствии onnxruntime.
- Два native AEC-теста пропущены: pywebrtc_audio не установлен в этой среде.
- Windows PowerShell и opt-in HTTPS download также пропущены.
- Сеть/LLM/модели/микрофон/голоса не загружались ради тестов.

Набор не доказывает native AEC3, качество распознавания/голоса, реальную
отмену через колонки, UI/DPI/трей/COM или безопасность внешнего кода.

## Проверка локальной кодировки Windows

Все 15 присланных UnicodeDecodeError воспроизведены в тестовом окружении с
CP1251 как default для Path.read_text/write_text: 15 failed, 104 passed.
После явного encoding="utf-8" в 36 местах восьми тестовых модулей тот же
набор с новым encoding guard: **130 passed** при CP1251 по умолчанию.
Симулятор не включён в приложение/ZIP и не меняет реальные системные настройки.
Это проверка текстового I/O, не нативный Windows-прогон всего приложения.
Runtime и пользовательские файлы не перекодируются; errors=ignore/replace
для обхода этих ошибок не добавлялись. Повтор полного Windows pytest — у пользователя.

## Приёмка комплекта

- 50 относительных ссылок входных документов проверены, сломанных нет.
- Три исходных DOCX совпадают byte-for-byte с предоставленными файлами.
- Полный source ZIP проверен на CRC и точное совпадение содержимого с рабочей
  копией; пути не выходят из каталога извлечения.
- Исключены личные JSON/профили/логи/записи голоса/модели/venv/build/dist.
  Лицензированные штатные звуковые ресурсы оставлены вместе с происхождением.
- В извлечённой чистой копии snapshot.py --check актуален и resource preflight
  проходит. Непроверенные Windows-функции остаются явно отмечены в PROJECT/PLAN.

## Восстановление модулей после ошибки копирования

Правильные версии password primitives, PasswordStage и трёх __init__.py
различаются и проверены в исходном ZIP. Присланный CI traceback соответствует
другому содержимому этих путей: самoимпорту password и отсутствующему __version__.
Причина изменения файлов на целевой стороне без их копии не установлена.
Пакет восстановления сохраняет вложенные пути и не содержит DOCX; не копировать
одноимённые файлы по отдельности/в одну папку. DOCX не нужны приложению и теперь
не влияют на snapshot. Нельзя выдавать Linux-проверку за повтор Windows CI.
