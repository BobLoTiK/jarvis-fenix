# Запуск без рабочего Whisper: DLL-ошибка CTranslate2

Это предшествующий узкий патч, включённый в общий пакет
[надёжности первого запуска](WINDOWS_STARTUP_RELIABILITY.md). Текущий статус
VC++/HTTPS/TTS и inference-time CPU fallback смотри там; приёмка старой
диагностической сборки не означает приёмки новых исходников.

## Что подтверждено

В диагностическом запуске установленного Феникса 2.1.0 в Windows Sandbox:
`jarvis/main.py` → импорт `faster_whisper` → `ctranslate2` → `ctypes.CDLL` →
`FileNotFoundError: Could not find module ...ctranslate2.dll (or one of its dependencies)`.
Процесс завершился с кодом 1 до основного окна, после пропуска настройки Ollama.
Это отдельное подтверждённое падение приложения, не причина общего падения Sandbox.

Старый предварительный импорт перехватывал только ImportError. FileNotFoundError
наследуется от OSError и выходил из main() без fallback, хотя Whisper необязателен.

## Исходный патч

- `_preload_whisper_backend()` сохраняет порядок faster_whisper → ctranslate2.
- При ImportError/OSError пишет исходный traceback и возвращает False.
- main() продолжает создание Vosk/GUI/ядра без Whisper; заведомо неисправный backend
  повторно не импортируется и не загружает модель в этом запуске.
- Успешный backend сохраняет прежнюю ленивую загрузку. `use_whisper` и другие
  настройки не меняются; пакеты не удаляются и не переустанавливаются.
- Safety, finalize_stream, история, locks, barge-in, общий PCM, LLM и TTS не менялись.

Это не установка отсутствующих библиотек, не гарантия готовности всего приложения
и не перехват нативного access violation. Другие обязательные DLL/устройства могут
выявить следующий независимый блокер. Лаунчер по-прежнему не подтверждает readiness GUI.

## Продолжить текущую Sandbox без изменения старой сборки

Whisper уже присутствует в venv по traceback. Не нужно сразу переустанавливать его
или скачивать другую модель. В Windows CTranslate2 требует Visual C++ Runtime:
[официальная документация](https://opennmt.net/CTranslate2/installation.html).
Наличие проблемы именно с этим runtime пока не доказано — это следующий контрольный шаг.

1. На основном ПК скачай [официальный Microsoft VC++ Runtime x64](https://aka.ms/vc14/vc_redist.x64.exe).
2. Скопируй файл в текущую Sandbox и установи там, согласившись с лицензией.
   Не запускай случайные DLL-паки и не копируй отдельные DLL с неизвестных сайтов.
3. Снова открой `start_fenix_debug.bat` в установленной папке Феникса.
4. Сохрани вывод/логи и отметь, изменился ли traceback. Успешная установка runtime
   сама по себе не подтверждает работоспособность Whisper или модели.

[Страница Microsoft с требованиями и ссылками](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist).
Если runtime требует перезагрузку, не закрывай Sandbox без сохранения логов:
обычное закрытие уничтожает её среду. Не объявляй перезагрузку успешной проверкой.

## Применение файлов

Архив патча распаковывается содержимым в корень исходного проекта jarvis с заменой.
README-дизайн не откатывается. Пользовательские конфиги/профили/модели не включены.
Для следующей поставки обнови исходники и собери новый Setup на Windows.
Этот пакет не содержит готовый EXE/Setup.

Чтобы сначала продолжить проверять именно прежний установленный Setup, примени
только ручной VC++-шаг в Sandbox; не копируй туда патч одновременно. Иначе результат
относится уже к изменённой установке, а не к исходной сборке.
