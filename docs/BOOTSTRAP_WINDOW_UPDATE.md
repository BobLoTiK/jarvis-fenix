# Единое окно подготовки (Unreleased, поверх 2.1.0)

## Что изменено

Вместо цепочки штатных Windows MessageBox лаунчер использует одно окно в графитово-медной теме. Оно не зависит от установленного Flet: используется Tk, Tcl/Tk включается в EXE стандартным hook PyInstaller. Сборщик должен иметь Python с компонентом Tcl/Tk; build_exe.py проверяет Tcl-интерпретатор перед сборкой. При запуске исходников нужен Tcl/Tk из базовой установки Python 3.11.

- Информация о создании окружения, загрузках, распаковке и запуске обновляет это же окно, без ожидания очередного «ОК».
- Имеющиеся вопросы согласия сохранены, но показаны внутри окна. Если Python отсутствует, вопросы перед Python и перед pip могут быть отдельными этапами в **одном** окне.
- Загрузки Python/Vosk показывают переданный urllib реальный объём; если Content-Length известен — долю загрузки. Общего процента всех работ нет.
- Во время pip показан этап и непрерывный индикатор работы, не выдуманный процент. Вывод отдельных пакетов в реальном времени пока не добавлен: команда и прежний capture_output не менялись.
- Ошибка остаётся в том же окне: «Повторить», «Закрыть», «Журнал». Повтор проверяет текущее состояние, не стирает данные.
- Отказ доступен на вопросе **до начала соответствующего этапа**. Принудительная отмена активной установки отключена; крестик/Escape не убивают процесс. Это намеренное ограничение данного патча.
- Официальный установщик Python и системные запросы прав могут открывать свои окна. Они не маскируются.
- При очень быстром запуске окно остаётся скрытым. При более долгой проверке появляется; закрывается после передачи управления процессу Феникса, не после подтверждения готовности его GUI.
- Обычный MessageBox оставлен только как аварийный fallback, когда само окно подготовки не удалось открыть, а также для прямого вызова функций без UI-контекста.

## Что не менялось

Команды дочерних процессов, набор dependencies, загрузочные URL, алгоритм установки Python/pip/Vosk, проверки и расположение данных сохранены. Управление процессами, активная отмена и новый механизм распаковки в этот патч не входят. TTS не изменён.

Поддерживаемая цель: Windows 10/11 x64. Inno явно задаёт MinVersion=10.0; работа на Windows 7/8, 32-bit, ARM без проверки или управляемых корпоративных ПК с запретами установки не обещается. Для подготовки недостающих компонентов нужен интернет и права записи в папку установки.

## Как собрать и проверить

Замены Python-файлов недостаточно для уже скомпилированного старого Феникс.exe: **EXE и Setup надо пересобрать на Windows**.

```powershell
.\.venv311\Scripts\python.exe -m pip install -r requirements-dev.txt Pillow
.\.venv311\Scripts\python.exe scripts\build_setup.py --check
.\.venv311\Scripts\python.exe scripts\build_setup.py
```

Нужен Inno Setup 6 и Python с Tcl/Tk. В CI Windows используется тот же build_exe.py. В EXE ожидаются стандартные PyInstaller hooks для tkinter/_tkinter с Tcl/Tk; это нужно подтвердить реальной сборкой и чистой установкой, не одним тестом импортов.

1. Проверить frozen EXE на Windows без заранее установленного Flet и, желательно, в новой виртуалке без Python. Не удалять рабочий Python/venv автора ради теста.
2. На вопросе выбрать «Не сейчас»: установка соответствующего этапа не начинается, окно закрывается без ошибки.
3. Согласиться: этапы идут в одном окне без промежуточных «ОК»; GUI остаётся отзывчивым, журнал открывается.
4. Проверить настоящий размер загрузки и отсутствие фиктивного процента pip. На сетевой ошибке — понятная ошибка и повтор в том же окне.
5. Во время pip крестик не завершает установку; это явно указано. Проверить обычное завершение и передачу управления приложению.
6. Уже настроенный повторный запуск не ставит зависимости заново. Проверить уведомление о работающем экземпляре.
7. Масштаб Windows 100/125/150%, длинные сообщения, Tab/Enter/Escape, минимум 1366×768; повторить на Windows 10 и 11.
8. Подтвердить включение Tcl/Tk и его license-файлов в результат сборки, отсутствие требования установить Tk отдельно на целевом ПК.

Linux-проверка — headless тесты логики, очередь UI, исходники и состав поставки. Реальная отрисовка Tk на Windows и EXE/Setup здесь не проверялись; без этой приёмки не считать исправление доказанно готовым для всех поддерживаемых машин.

Если v2.1.0 уже опубликован, не перезаписывать тег/старые бинарники: выпускать исправление новым тегом после приёмки. Версия пакета данным интерфейсным патчем автоматически не повышается.
