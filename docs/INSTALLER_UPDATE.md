# Поставка и обновление Феникса

## Что изменено

- Inno Setup получает curated `build/release-payload`, а не произвольное содержимое рабочей папки. Включены новая Главная, аура, кольцо действий, виджеты, темы, бренд-ресурсы и звуковые реакции.
- Конфиги, профили, история, задачи, логи, модели, venv и диагностика сборщика не включаются. `config.example.json` оставляет виджеты и быстрые действия пустыми.
- `release-manifest.json` содержит относительные пути и SHA-256 поставляемых файлов. Это контроль состава, **не цифровая подпись и не защита от подмены загрузки**.
- Inno проверяет mutex ядра и setup-лаунчера. При обновлении сохраняются `.venv311`, модели и `%APPDATA%\Phoenix`; код перезаписывается. Для надёжности сначала выбери «Выход» в меню трея.
- Лаунчер использует Python 3.11 и `.venv311`. Fingerprint requirements + проверка Flet/native client позволяют заметить устаревшее окружение; установка пакетов требует согласия и интернета. Даже существующее окружение без receipt пройдёт проверку/подготовку один раз.
- Поддерживаемая линия Flet: `>=1.0.3,<1.1`, версии Python-пакета и desktop-клиента должны совпадать. Это не обещание совместимости с ещё не выпущенными версиями.
- `scripts/check_caps.py` пишет атомарно в `%APPDATA%\Phoenix\system_caps.json`; запускается на компьютере пользователя. Ошибка диагностики не блокирует старт; старый корневой кэш сборщика не используется. Чтобы переснять диагностику: `.venv311\Scripts\python.exe scripts\check_caps.py`.
- `install.bat` не ставит внешний eSpeak через winget и не выбирает/скачивает LLM без явного выбора. При неуспешном pull выбранная модель не записывается в конфиг.
- Ярлык не вставляет пользовательские пути в PowerShell-код; обычный BAT-запуск идёт через лаунчер, debug — напрямую в выделенное окружение.
- Баннеры установщика используют графитово-медную тему и переданную версию релиза. GitHub workflow валидирует версию и передаёт значения через окружение, а не вставкой в код PowerShell.

## Сборка на Windows

Из полного исходного проекта (не из установленного runtime):

```powershell
py -3.11 -m venv .venv311
.\.venv311\Scripts\python.exe -m pip install -r requirements-dev.txt Pillow
.\.venv311\Scripts\python.exe scripts\build_setup.py --check
.\.venv311\Scripts\python.exe scripts\build_setup.py
# При необходимости: --version 1.0.2
```

Нужен Inno Setup 6. `INNO_SETUP` может указывать на `ISCC.exe` или его папку; иначе используется PATH/стандартные пути. `--check` проверяет исходные ресурсы и installer.iss без скачиваний, EXE, диагностики железа и вызова Inno; он не заменяет реальную компиляцию и тест установки. Результат сборки — `Феникс.exe` и `dist\Феникс_Setup.exe`. Отдельный EXE — bootstrap-лаунчер, не полностью автономное приложение; распространять пользователям следует Setup.

## Что проверить на Windows

1. Чистая установка: ярлыки, первый запуск, согласие/отмена загрузки пакетов, окно и иконка трея.
2. Обновление в ту же папку: профиль, задачи, быстрые действия, настройки, модели сохранены; другой пользователь не получает данные сборщика.
3. Запущенный Феникс/подготовка окружения: Setup просит закрыть приложение, не перезаписывает работающие файлы молча.
4. Запуск из пути с пробелами/кириллицей; ярлык из пользовательского пути с апострофом. Проверь установку модели в ASCII program-dir.
5. Главная/Диалог/звук, обе темы, раскрытие панели **со сдвигом контента**, аура и кольцо, добавление/сохранение виджетов.
6. Изменённый requirements/несовместимый native Flet → предложение обновления; Отмена не запускает pip.
7. Повторный запуск использует receipt; локальный caps находится в USER_DIR. Bootstrap-лог остаётся `logs\launcher.log` рядом с лаунчером; рабочие логи — в USER_DIR.

Локальная проверка исходников выполнялась на Linux. Windows EXE и Inno Setup здесь не компилировались; системный трей, аудио и реальная установка требуют перечисленной проверки на Windows.

## Что не менялось

Это аудит установки, а не новая оптимизация TTS. Пакеты облегчённых голосов, ограничение CPU-потоков и улучшенное перекрытие Ollama/озвучки ещё не реализованы. Существующий `auto` по-прежнему Silero → Piper → WinRT → SAPI. Не обещаем отсутствие нагрузки и не меняем модель/голос пользователя автоматически.
