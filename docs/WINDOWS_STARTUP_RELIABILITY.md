# Первый запуск Windows: пакет исправлений

## Что известно из Sandbox

Это журнал результатов, не подтверждение чистой установки новой сборки.
В старой сборке пользователь вручную поставил VC++ x64, запускал временный
TLS-helper с certifi и выбрал Piper. После этого подтвердил все три пункта:
Проводник открылся, следующая команда принимается, ответ слышен.
Notepad отсутствовал: actions.log содержит WinError 2 для notepad.exe.
Отдельное падение самой Sandbox при установке Ollama этим не объяснено.

## Что изменено в исходниках

1. **VC++ x64.** Лаунчер пробует загрузить три runtime DLL по полным путям
   System32. Если они недоступны, спрашивает согласие на скачивание и открытие
   официального Microsoft Redistributable. Windows PowerShell использует TLS 1.2;
   Authenticode должен быть Valid, издатель — Microsoft Corporation. Подпись
   проверяется при загрузке и повторно непосредственно перед запуском.
   Установщик открывается интерактивно, не тихо; лицензию/UAC подтверждает человек.
   «Проверить» заново проверяет DLL, а не считает открытие установкой.
   Отказ останавливает подготовку, не скачивает и не ставит компонент молча.
   Это проверка загрузки DLL, не обещание пригодности любого нативного пакета.
2. **HTTPS приложения.** Явная лёгкая зависимость certifi уже использовалась
   транзитивно. Вход `python -m jarvis` настраивает SSL_CERT_FILE до main/Flet/torch.
   Существующие SSL_CERT_FILE/SSL_CERT_DIR не заменяются: частные CA задаются
   администратором. Изменение только в текущем процессе и его потомках, без
   системного хранилища, реестра и правок site-packages. Проверка цепочки и имени
   сервера не отключается. Certifi не гарантирует работу через частный TLS proxy.
3. **Клиент Flet.** Отдельный Python helper вызывает публичный
   ensure_client_cached и проверяет cache/flet/flet.exe. Этап выполняется пока
   окно подготовки может показать ошибку/повтор, а не впервые внутри скрытого GUI.
   Лаунчер ждёт helper до 240 секунд и требует успешный exit + маркер готовности.
   При ошибке основной процесс не запускается. Кэш пользователя не удаляется.
   Это подготовка бинарного клиента, **не handshake готовности основного GUI**.
4. **Ожидание TTS.** Пока единственный фоновый loader готовит голос, ответ ждёт
   готовность до 1 секунды и остаётся текстовым, если голос не готов. Повторный
   синхронный init под занятым lock больше не вызывается. Старая реплика позже
   сама не озвучится. После готовности голос используется следующими ответами.
   Stop/barge-in выходит из ожидания обычной реплики даже при живом native worker;
   для одной текстовой реплики есть предел ожидания 120 секунд + join до 2 секунд.
   Новая озвучка не запускается поверх незавершившегося старого play_async.
   Смена движка не ждёт занятый init-lock; неудачная живая смена не означает,
   что выбранный в конфиге backend не будет применён при следующем запуске.
   Native loader не убивается принудительно. Auto-порядок остаётся
   Silero → Piper → WinRT → SAPI. Это не новая очередь и не ускорение синтеза.
5. **Запуск приложения.** Ответ для известного приложения, именованного браузера
   с app-spec и Steam учитывает bool actions.run_spec. Неудачный вызов не
   сопровождается «Открываю». Успешный Popen не доказывает появления окна —
   это не подтверждение готовности всех программ и не исправление всех действий ОС.
6. **Whisper.** Ошибка CUDA/cublas/cuDNN перехватывается также при потреблении
   ленивого генератора сегментов. Одна попытка CPU int8 берёт **ту же модель**
   из локального кэша; local_files_only=True, без установки CUDA/скачивания
   другой модели. При отсутствии кэша/отказе CPU backend недоступен до нового
   запуска; main использует только достаточно уверенный Vosk. Проверка качества
   Whisper не ослаблена. Успешный конструктор GPU больше не выдаётся за успешный
   inference. На больших моделях CPU может быть медленным; замеров здесь нет.
   Ожидание уже запущенной фоновой загрузки ограничено 1 секундой; пока модель
   готовится, остаётся исходный gate Vosk, а не обход уверенности.

Включено прежнее исправление optional ImportError/OSError CTranslate2:
[WHISPER_STARTUP_DLL_FIX.md](WHISPER_STARTUP_DLL_FIX.md).
Нет изменения use_whisper, профилей/истории, пользовательской модели Ollama,
приоритета TTS, safety/finalize_stream, Vosk, cmd_lock/_say_lock или GUI-вёрстки.
Гонка событий стриминга Диалога не объявлена устранённой.

## Применение

1. Закрой Феникс, включая трей и диагностическую консоль. Сохрани свои изменения
   исходников отдельно. Распакуй файлы ZIP прямо в корень проекта с заменой:
   рядом должны оказаться launcher.py, launcher_runtime.py, jarvis и scripts.
2. Пересобери **и EXE, и Setup** через workflow build-release вручную
   (workflow_dispatch) либо Windows `python scripts/build_setup.py`.
   Замена Python-файлов в проекте не обновляет уже собранный frozen launcher.
3. Старый опубликованный v2.1.0 не передвигай. Для публичного выпуска используй
   новую patch-версию после приёмки; этот пакет сам Release/tag не создаёт.

В ZIP нет личных JSON, диагностических BAT, моделей, окружения или Windows EXE.
README и его иллюстрации не переделывались.

## Windows-приёмка новой сборки — ещё не выполнена

В чистую среду перенеси только новый Setup. Начни обычным ярлыком, не временным
TLS/Piper BAT. Интернет для подготовки нужен. Проверь явный запрос VC++ при
недоступных DLL, отказ без установки, согласие и реальную проверку после установки.
Окно подготовки должно показать этап клиента Flet и ошибку/повтор при недоступной
загрузке. Выбери продолжение без Ollama. Проверь Explorer вместо отсутствующего
Блокнота, следующую команду, голос после готовности, Stop, выход и повторный запуск.
Для проверки отказа приложения отсутствующий Notepad должен дать честную ошибку.

Дополнительные сценарии: долгий/ошибочный TTS init без зависания команды;
GPU constructor успешен, decode падает → cached CPU или уверенный Vosk;
нет Whisper DLL → GUI/Vosk; private CA не заменяется; TLS-сбой не обходится.
Краш всей Sandbox с кодом Windows исследовать отдельно, не объявлять его
доказанным дефектом Феникса. Микрофон/перенаправление звука Sandbox также
проверяются отдельно от успешной текстовой команды.
