# Феникс 2.1.2

Патч поверх 2.1.1. Опубликован как
[релиз v2.1.2](https://github.com/BobLoTiK/jarvis-fenix/releases/tag/v2.1.2); тег
`v2.1.2` аннотированный и стоит на коммите `529b495`, тег `v2.1.1` не перемещался —
там уже опубликованный предыдущий выпуск, а переделка TTS вместе с полной сборкой
Nuitka выходит новой версией.

**Пересборка 02.11.2026.** Вложения этого релиза заменены на сборку с коммита
`db2f983` (тег `v2.1.2` намеренно оставлен на `529b495`: перенос тега ломает
клоны, а номер версии не меняется). Что вошло в пересборку — раздел
«Пересборка 02.11.2026» ниже.

## Главное

- **Переделан жизненный цикл TTS.** Смена backend, голоса, качества и темпа больше не
  выполняется в обработчиках GUI: всё идёт через один фоновый worker с ревизиями и откатом,
  а проба голоса и незавершённая озвучка больше не накладываются друг на друга.
- **Появился второй, автономный вариант поставки.** `Феникс_Fast_Setup.exe` содержит
  собственный Python, Flet desktop client и нативные библиотеки: внешние Python, pip и
  `.venv311` у пользователя не нужны. Прежний bootstrap-лаунчер `Феникс_Setup.exe`
  остаётся для тех, кому нужен маленький установщик.

## Переделка жизненного цикла TTS

- Загрузка и смена backend, голоса, качества и темпа вынесены в один фоновый worker с
  ревизиями: неудачное переключение откатывается, статус готовности обновляется только по
  факту готовности.
- Проба голоса отменяется до окончания подготовки, поздний WAV не проигрывается; поверх
  незавершённой озвучки не запускается новая.
- Все операции SAPI/pyttsx3 выполняются на одном COM-owner потоке; кнопка Stop из GUI
  передаёт только сигнал. Silero больше не читает скрытый stdin-запрос доверия.
- Закрытие окна Flet стало асинхронным и не блокирует выход.
- Применение, ручная приёмка и ограничения: [TTS lifecycle](../TTS_LIFECYCLE_FIX.md).

## Полная сборка Nuitka (вторая поставка, standalone)

- Новый путь: `phoenix_app.py` → standalone → `Феникс_Fast_Setup.exe`. Внутри свой Python,
  Flet desktop client и нативные библиотеки; внешний Python не требуется.
- Сборка проверяет XML compiler report и SHA-256 manifest, затем запускает native probe самой
  сборки; отдельный offline-сценарий Windows Sandbox проверяет установку, импорт DLL,
  GUI-smoke, удаление и сохранение пользовательских данных.
- Добавлен consent-based `--prepare-silero` на встроенном runtime.
- Описание процесса и ограничений: [FULL_NUITKA_BUILD](../FULL_NUITKA_BUILD.md).
- По итогам реальной сборки исправлено: пакет `flet` включается целиком (иначе падал
  `flet.controls.material.icons`), добавлены данные пакета `winrt` (winrt 4 читает таблицу
  проекций рядом с модулем), `torch.testing._internal` исключается только тяжёлыми тестовыми
  модулями (иначе не работает `import torch`), отчёт Nuitka с `encoding='utf8'` разбирается
  корректно, а harness песочницы сделан ASCII-совместимым для Windows PowerShell 5.1.
- Добавлен `--skip-compile` для повторного использования готового standalone и `--jobs 5`
  вместо однопоточного режима.

## Пересборка 02.11.2026

Первая сборка 2.1.2 падала на чистой Windows: `pip` спотыкался о кириллицу в
комментариях `requirements.txt` (кодировка локали), скачивание модели Vosk шло
без общего CA-бандла, а автономная сборка не находила перераспространяемый
Visual C++. Плюс заменились вложения. В новой сборке:

- `requirements*.txt` начинаются с `# -*- coding: utf-8 -*-`; лаунчер подключает
  `jarvis.https_trust` до первых загрузок; у `pip install` в журнале виден хвост вывода.
- Автономная сборка несёт MSVC-рантайм (`msvcp140*.dll`, `vcruntime140*.dll`,
  `concrt140.dll`, `mfc140u.dll`) — `--self-test` на машине без VC++ проходит.
- Вкладки «Движки» и «Облако»: выбор провайдера/модели облачного LLM, статусы
  Vosk/Faster-Whisper/Piper, ручная проверка пакетов.
- У `Феникс.exe` появился ресурс версии (обе сборки): «Свойства → Подробно» теперь
  показывают 2.1.2, название продукта и описание.
- Яркость отвечает за 1,5 с вместо 7: опрос DDC/CI ограничен по времени.
- Слушатель без микрофона больше не пишет полную трассировку каждые 10 секунд.
- Версии сборщика зафиксированы (`pyinstaller==6.22.3`,
  `pyinstaller-hooks-contrib==2026.8`): сборка воспроизводима, и содержимое exe
  перестало разъезжаться между CI и локальной машиной.

## Установка и обновление

- `Feniks_Setup_2.1.2.exe` — прежний bootstrap-вариант: при первом запуске нужен
  интернет, чтобы поставить зависимости и скачать модель.
- `Feniks_Fast_Setup_2.1.2.exe` — автономный вариант: ставится в тот же каталог и
  обновляет существующую установку (тот же `AppId`), внешний Python и сеть не нужны.
- Имена файлов в релизе латиницей намеренно: GitHub вырезает не-ASCII из имён
  вложений, из-за чего прошлые релизы получали `_Setup.exe` и `default.exe`.
- Оба установщика NotSigned: SmartScreen покажет предупреждение при первом запуске.

## Собранные артефакты

- `Feniks_Setup_2.1.2.exe` — лёгкий установщик, около 15 МБ.
- `Feniks_Fast_Setup_2.1.2.exe` — автономный установщик, около 295 МБ.
- Точные размеры и SHA-256 обоих файлов — в приложенном `SHA256SUMS.txt`.
- Версия `2.1.2` в `jarvis/__init__.py`, `installer.iss` и `installer_nuitka.iss`.

## Проверки и ограничения

- Windows-прогон: `check_all.py` — 4/4; pytest — полный набор зелёный и в `.venv311`,  и в окружении `requirements-ci.txt`; `snapshot.py --check` актуален;
  `build_setup.py --check` — публичные файлы без личных данных.
- `--self-test` автономной сборки из CI: `ok: true`, 31 проверка, ни одного провала
  (`external_python_required: false`).
- Установка проверена в чистой Windows 11 (Hyper-V): лёгкий установщик ставится и
  поднимает приложение (venv, зависимости, модель Vosk, клиент Flet), автономный —
  установка около минуты, `--self-test` и `--gui-smoke` зелёные, окно работает,
  удаление без остатков.
- Не проверено: микрофон и живой звук (в ВМ нет устройства), Ollama (пропускали
  осознанно), GPU-инференс.
- Отдельный риск: в окружении сборки winrt 4.0.3, а в `.venv311` — 3.2.1; `requirements.txt`
  не ограничивает версию сверху. Media Control на winrt 4 не проверялся.
- Оптимизация нагрузки TTS рядом с Ollama в 2.1.2 **не входит**; очередь TTS, семантический
  слой и проверка консенсусом остаются следующими блоками.
