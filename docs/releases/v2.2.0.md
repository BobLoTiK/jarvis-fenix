# Феникс 2.2.0

Первый опубликованный выпуск после 2.1.2: в него входит всё, что готовилось в
2.1.3 (тег `v2.1.3` так и не создавали), плюс новая возможность — Феникс сам
узнаёт о новой версии на GitHub, скачивает нужный установщик со сверкой SHA-256 и
ставит его поверх текущей версии по кнопке, а затем возвращается сам. Тег и релиз
`v2.2.0` не создавались: их создание — отдельное решение пользователя.

## Главное

- **Обновление без ручного поиска установщика.** «Настройки» → карточка
  «Обновления»: статус, «Проверить обновления», «Скачать обновление» →
  «Установить и перезапустить», текст заметок релиза и ссылка на страницу
  релизов. Галочка «Проверять при запуске» делает один фоновый запрос к
  `api.github.com` за запуск (`update_check_enabled`, по умолчанию включена).
- **Ставится ровно тот установщик, который соответствует сборке.** Обычная
  установка получает `Feniks_Setup_<версия>.exe`, автономная Nuitka-сборка —
  `Feniks_Fast_Setup_<версия>.exe` (её установка идёт через UAC). Из папки
  проекта обновление не ставится: там своя жизнь и `.git`.
- **Ничего не устанавливается само.** Проверка и скачивание — сеть, установка —
  только по нажатию кнопки, в тихом режиме, поверх текущего каталога.

## Как это устроено

1. `jarvis/updater.py` читает `releases/latest` и сравнивает версии по числовым
   частям. Теги с суффиксом (`-rc1`) не предлагаются, ответ разбирается строго:
   только ожидаемые имена ассетов, только https и хосты GitHub, ограниченный
   размер тела.
2. Установщик качается в `%APPDATA%\Phoenix\updates` потоково, в `.part`.
   Размер сверяется с релизом, SHA-256 — с `SHA256SUMS.txt` релиза и/или полем
   `digest` из API. Файл переименовывается только после проверки; при ошибке
   остаётся только понятное сообщение, `.part` удаляется.
3. Помощник `apply_update.ps1` (тоже в `%APPDATA%\Phoenix\updates`, а не в
   каталоге программы) ждёт завершения Феникса, освобождения мьютексов ядра и
   лаунчера, **заново** сверяет SHA-256, запускает установщик с
   `/VERYSILENT /SUPPRESSMSGBOXES /NOCANCEL /CLOSEAPPLICATIONS /NORESTART /SP-`
   и `"/DIR=<текущий каталог>"` / `"/LOG=<журнал>"` — значения в кавычках,
   потому что путь установки может содержать пробел (`C:\Program Files\Phoenix`
   у автономной сборки). Затем сверяет `ProductVersion` установленного
   `Феникс.exe` с целевой версией, пишет `last_update.json`, удаляет скачанный
   установщик и запускает Феникс снова.
4. Феникс при следующем старте показывает тост об итоге прошлой установки. Если
   UAC отказали, установщик вернул ошибку или файл подменили после проверки —
   запускается прежняя версия, а окно с причиной показывается уже после
   возврата приложения.
5. Скачивание можно прервать кнопкой «Отменить скачивание»; недокачанный `.part`
   удаляется. Пока идёт проверка или скачивание, нажатие кнопок сообщает, что
   действие уже выполняется, а не молчит.

## Что сохраняется

`config.json`, профили, история, память, модели и `%APPDATA%\Phoenix` не
трогаются: установщик ставится поверх кода, `UsePreviousAppDir`/`/DIR` указывают
на текущий каталог. Это проверено на установке 2.1.3 поверх 2.1.2 и повторено
12.11.2026 настоящим установщиком с набором ключей выше.

## Честные границы

- Оба установщика **не подписаны**: UAC спрашивает про неизвестного издателя.
  SHA-256 из того же релиза защищает от битого или подменённого при скачивании
  файла, но не заменяет подпись автора. Это написано в самой карточке.
- Успех установки подтверждается `ProductVersion` файла, а не только кодом
  выхода установщика. Поэтому релизный тег обязан совпадать с `__version__` в
  `jarvis/__init__.py`: при забытом bump установка встаёт, но помощник честно
  сообщает «не установлено», и приложение предлагает тот же релиз по кругу.
  Теперь это проверяет CI до сборки (`.github/workflows/release.yml`).
- Сквозная цепочка проверена 12.11.2026 локальным e2e с настоящим установщиком:
  база 2.2.0 → «опубликованный релиз 9.9.9» → проверка → выбор ассета по типу
  сборки → скачивание с SHA-256 → `apply_update.ps1` → тихая установка поверх →
  `ProductVersion` 9.9.9 → перезапуск → `{"status":"ok"}`. Сеть подменялась
  только на отдачу JSON и байтов файла, всё остальное — настоящий код и
  настоящий Inno Setup. Отдельно проверено, что `/DIR` с пробелом в пути
  ставит файлы именно в указанный каталог; найденный при этом дефект (кавычки
  вокруг значения) исправлен.
- Непроверенным остаётся: публичный релиз на GitHub новее этой сборки и
  автономная (Nuitka) сборка, где установка идёт через UAC. Проверка
  `install_kind()` для скомпилированной копии добавлена в self-test сборки.
- Отката нет: при неудаче остаётся прежняя версия (установщик либо не запустился,
  либо не изменил `ProductVersion`), но «вернуть предыдущую сборку» — отдельная
  задача.

## Установка и обновление

Ставится поверх 2.1.2 — последнего опубликованного выпуска — обычным способом;
после появления релиза `v2.2.0` эту же версию можно ставить уже из карточки
«Обновления». Отключить проверку при запуске: `update_check_enabled: false` в
`config.json` или галочка в карточке. Подробности для пользователя —
`docs/USER_GUIDE.md`.
