# Облачная LLM в Фениксе

Феникс умеет отвечать не только локальной Ollama. Включённая облачная модель
делает две вещи, которые локальная не может: работает на слабом железе и
позволяет проверить Феникса **без Ollama вообще** — распознавание речи остаётся
локальным (Vosk), синтез берёт системный SAPI, а думает облако.

По умолчанию всё выключено. Ни один байт не уходит наружу, пока пользователь
сам не включит облако и не вставит ключ.

## Как включить

1. Настройки → **Облачная модель**.
2. Провайдер: OpenAI, OpenRouter, DeepSeek, Groq, Anthropic или «Свой адрес»
   (любой OpenAI-совместимый шлюз: vLLM, LM Studio, together, корпоративный прокси).
3. Адрес API и модель — подставляются из пресета, можно переписать.
4. Вставить ключ → **Сохранить ключ**. Поле после сохранения очищается,
   на экране остаётся только отпечаток.
5. **Проверить ключ** — дешёвый запрос списка моделей, без генерации и без списания токенов.
6. Включить «Отвечать через облако».

Ключ хранится отдельно от конфига, поэтому перенос `config.json` на другую
машину ключ не переносит — это сделано намеренно.

## Где лежит ключ и почему не «хеш»

- Ключ шифруется Windows DPAPI (`CryptProtectData`) и лежит в
  `%APPDATA%\Phoenix\secrets\cloud_llm_key.bin`.
- DPAPI привязывает шифрование к текущей учётной записи Windows: скопированный
  файл на другом компьютере или под другим пользователем не расшифруется.
  Дополнительно подмешивается энтропия с именем продукта.
- Хешировать ключ нельзя: хеш необратим, а ключ нужно отправлять провайдеру.
  Хеш применяется в другом месте — для **отпечатка** (первые 8 символов
  SHA-256), чтобы человек мог сверить «тот ли ключ сохранён», не показывая
  ключ ни на экране, ни в логе.
- В `config.json` ключа нет и быть не должно: конфиг читают глазами, он уезжает
  в диагностику и живёт в профиле.
- Значение никогда не логируется. В журнал попадает имя секрета, длина и отпечаток.
- Кнопка **Удалить ключ** стирает файл; после этого облако сразу перестаёт работать.

## Что уходит в облако

| Данные | По умолчанию | С `cloud_send_profile=true` |
|---|---|---|
| Системная инструкция Феникса | уходит | уходит |
| Текст вашей реплики | уходит | уходит |
| История диалога (если передана) | уходит | уходит |
| Персона, настроение | **нет** | уходит |
| Факты из памяти (RAG) | **нет** | уходит |
| Профиль, файлы, config, логи | **нет** | **нет** |

Переключатель «Отправлять в облако персону и память» — единственный способ
отправить личные блоки. Он выключен, и это осознанное решение: у провайдера
эти данные уже нельзя отозвать.

При сохранении этого переключателя Феникс пишет в профиль
пользователя запись `cloud_consent`:

```json
{"cloud_send_profile": true, "version": 1, "at": "2026-10-30T12:00:00+00:00"}
```

Это след, а не гейт: решение по-прежнему принимает переключатель в
`config.json`. Запись нужна, чтобы потом можно было ответить, когда и в какой
редакции текста человек разрешил отправку, — и чтобы отзыв согласия тоже
остался видимым (`cloud_send_profile: false`). В карточке настроек под
переключателем показано текущее состояние согласия.

## Технические ограничения, зашитые в код

- **Только https.** Открытый `http` разрешён исключительно для `localhost`:
  по открытому каналу ключ ушёл бы в сеть в читаемом виде.
- Логин/пароль внутри URL запрещены — ключ передаётся только заголовком
  (`Authorization: Bearer` для OpenAI-совместимых, `x-api-key` + `anthropic-version`
  для Anthropic).
- Текст ошибок прогоняется через редакцию: ключ вырезается, тело ответа
  обрезается. Ошибка 401/403 даёт короткое «Ключ не принят», а не тело запроса.
- Испорченный или подменённый файл ключа не расшифровывается: DPAPI проверяет
  целостность блоба. Проверено тестом (обрезание и подмена байта).
- Модуль `jarvis/cloud_llm.py` не добавляет в запрос ничего своего: ни профиля,
  ни истории, ни памяти. Что передал `brain.py`, то и уйдёт.

## Стриминг

`chat_stream` поддерживает SSE обоих протоколов: чанки отдаются по мере прихода,
ответ озвучивается частями так же, как у Ollama. Отмена — та же, что и раньше
(стоп-токен в `Speaker`).

Если провайдер присылает ошибку внутрь потока (событие `error` у Anthropic,
кадр `{"error": …}` у OpenAI-совместимых шлюзов), это `CloudLLMError` с
вырезанным ключом, а не пустой ответ. Уже произнесённые чанки не отзываются:
речь не переписывается задним числом. Перед отправкой в Anthropic роли
нормализуются (соседние реплики одной роли склеиваются, ведущий ответ
ассистента отбрасывается): иначе провайдер отвечает 400 «roles must
alternate».

## Стоимость и честность

- Запросы платные у выбранного провайдера; тарифы и лимиты — его дело,
  Феникс ничего не обещает.
- Если ключ отозван или кончился баланс, Феникс вернётся к локальной Ollama,
  если она доступна, и не будет молча выдумывать ответ.
- Проверка в тестах не заменяет живую проверку у провайдера: тесты идут на
  фейковом транспорте и ни одного сетевого запроса не делают.

## Проверка без Ollama (сценарий «чистая машина»)

Так Феникса можно принять целиком, не ставя Ollama и не качая LLM:

1. Установить Феникс. При первом запуске он скачивает модель Vosk (нужна сеть).
2. Вставить ключ облака и включить облачную модель.
3. Сказать «Феникс, привет» — Vosk распознаёт локально, облако отвечает,
   SAPI (встроен в Windows) озвучивает.

Ничего, кроме модели Vosk, для этого не требуется: TTS SAPI есть в системе.

## Откат

1. Настройки → Облачная модель → **Удалить ключ**.
2. Выключить «Отвечать через облако».
3. Феникс снова работает на локальной Ollama, настройки и память не тронуты.

## Тесты

`tests/test_cloud_llm.py`:

- транспорт на фейковом opener: заголовок вместо тела, `response_format` в JSON-режиме,
  Anthropic с `system` на верхнем уровне, оба стрима;
- утечки: ключ не появляется в `repr`, в теле запроса и в тексте ошибки;
- адрес: `http` наружу отклоняется, `http://127.0.0.1` разрешён;
- приватность: персона и факты **не** попадают в системный промпт, пока
  `cloud_send_profile` выключен, и попадают, когда включён;
- хранилище (только Windows): roundtrip, отпечаток, отсутствие ключа в открытом
  виде в файле, нерасшифровка испорченного блоба.
