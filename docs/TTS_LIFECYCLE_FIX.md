# Исправление загрузки, переключения и остановки TTS

## Подтверждённые причины

- Синхронные Config.subscribe → Speaker.set_voice/switch_backend вызывали
  загрузку/пересоздание движка в обработчике GUI. Тяжёлая загрузка задерживала окно.
- torch.hub запрашивал доверие репозиторию через stdin. В GUI вопрос был скрыт;
  ожидание input блокировало смену движка. Команда диагностики могла стать ответом.
- SAPI/pyttsx3 создавался и использовался в разных потоках, включая stop из GUI.
- После неудачной смены backend конфиг/список могли показывать новый backend,
  хотя озвучка оставалась на старом. Кэш также не различал качество модели.
- Остановка до окончания подготовки пробы могла теряться при создании нового токена.
- Flet Window.close — coroutine; старый вызов без await не закрывал окно штатно.

## Изменения

- Один daemon-worker `tts-settings` последовательно применяет изменения backend,
  голоса, качества и темпа. Обработчики настроек не ждут загрузку или native stop.
- Новые запросы объединяются. Ревизия защищает от публикации устаревшей загрузки,
  включая первоначальный `tts-init`. Загруженный движок меняется только после
  завершения предыдущего воспроизведения, без наложения звука.
- На время подготовки голосовая проба недоступна. Статус обновляется автоматически.
  Проба не ставится в очередь «на потом».
- Проба имеет отдельный Event отмены: отмена до старта worker, в ожидании готовности
  и во время синтеза сохраняется; отменённый WAV не воспроизводится.
- Stop устанавливает токен без ожидания модели. Сама уже начатая загрузка или native
  synthesis не убивается принудительно; результат отменённой пробы отбрасывается.
  Последний выбранный набор настроек применяется после завершения текущей загрузки.
- Ошибка переключения сохраняет предыдущий рабочий engine; конфиг возвращается
  через expected_values/CAS, не затирая более новый пользовательский выбор.
- Голос нормализуется под новый backend. Качество участвует в ключе кэша.
- Все COM/pyttsx3 операции SAPI, включая инициализацию и остановку, выполняет один
  `sapi-owner`. Caller/GUI передают только данные и сигналы отмены. Нет runAndWait
  в чужом потоке; owner запускает внешний цикл событий и обслуживает отмену.
- Если native-поток SAPI не подтвердил окончание, новая озвучка не запускается
  поверх него. Stop остаётся быстрым; не выдаём запрос отмены за завершение.
- Silero не запрашивает stdin из GUI. Без заранее сохранённого доверия выдаётся
  диагностическая ошибка; доверие новому репозиторию автоматически не добавляется.
- Асинхронный Window.close запускается через page.run_task и ожидается на loop Flet.

## Применение на Windows

1. Закрыть Феникс целиком, в том числе через «Выход» в трее. Если процесс остался,
   определить его по `python.exe/pythonw.exe -m jarvis` и завершить только его.
2. Сохранить резервные копии заменяемых исходников. Распаковать патч в `C:\jarvis`
   с заменой файлов, не в `dist` или `build`. Личные конфиги и модели патч не содержит.
3. Запустить из CMD:

```bat
cd /d C:\jarvis
".venv311\Scripts\python.exe" -u -X utf8 -X faulthandler -m jarvis
```

Это обновление runtime-кода `jarvis`, не скомпилированного launcher. Для данного
проверочного запуска пересборка Nuitka, установка зависимостей и удаление моделей
не нужны. Для отдельной поставки пересобрать/перепаковать её из обновлённого корня.

### Первое доверие Silero (если ещё не подтверждено)

Torch Hub выполняет код репозитория. Решение доверять `snakers4/silero-models`
принимает пользователь. При закрытом Фениксе, в видимой консоли без перенаправления:

```bat
cd /d C:\jarvis
set "TORCH_HOME=C:\ProgramData\Phoenix\torch"
".venv311\Scripts\python.exe" -u -c "import torch; torch.hub.load('snakers4/silero-models', 'silero_tts', language='ru', speaker='v5_5_ru'); print('SILERO READY')"
```

Если пользователь согласен доверять указанному репозиторию, ответить `y` на запрос.
При уже подтверждённом доверии и готовой модели этот шаг повторять не нужно.

## Ручная приёмка Windows

- Во время холодной загрузки менять backend/голос; окно остаётся доступным,
  после загрузки применяется последний выбор, не промежуточный.
- Нажать пробу и сразу stop, в том числе во время синтеза. Отменённая фраза
  не начинается позже; следующая проба работает без наложения.
- Повторить пробу → stop → смена голоса/движка для Piper, Silero и SAPI.
- При ошибке загрузки сравнить выбранный и фактически загруженный движки;
  проверить статус ошибки и откат, затем успешный новый выбор.
- «Выход» в трее закрывает окно без предупреждения `Window.close was never awaited`.

## Границы проверки

Переносимые тесты выполняются на Linux/Python 3.13 без реального микрофона,
Windows SAPI/COM, Flet desktop и загрузки моделей. Сценарии гонок воспроизводятся
управляемыми Event и fake native driver. Это не заменяет ручную Windows-приёмку.
Нативный зависший вызов нельзя безопасно убить в Python-потоке; патч сохраняет
запрет наложения и доступность GUI, но не обещает принудительное завершение DLL.
