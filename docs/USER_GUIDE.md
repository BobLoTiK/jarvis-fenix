## 💻 Требования

| Компонент | Условие |
|---|---|
| Windows 10/11 x64 | Основная платформа; GUI, COM/UIA и аудиостек проверять на Windows. |
| Python 3.11 | Проверенная версия — 3.11.9; окружение `.venv311`. |
| Микрофон | Для голоса; текстовые команды можно отправлять через чат. |
| VC++ Redistributable x64 | Нужен для нативных библиотек; [установщик](https://aka.ms/vs/17/release/vc_redist.x64.exe). |
| Интернет | Для установки зависимостей/моделей и сетевых функций. |
| Ollama | Необязательно: диалог и семантическая память. |
| NVIDIA GPU | Необязательно; производительность зависит от моделей и оборудования. |

Для Windows/Vosk не переходи на Python 3.13/3.14 без отдельной проверки DLL.
Не обещаем фиксированное потребление памяти: сначала выбирай модель под свой компьютер.

<a id="install"></a>
## 📥 Установка

### Из исходников

В PowerShell или терминале VS Code:

```powershell
git clone https://github.com/BobLoTiK/jarvis-fenix.git
cd jarvis-fenix
py -3.11 -m venv .venv311
.\.venv311\Scripts\python.exe -m pip install --upgrade pip
.\.venv311\Scripts\python.exe -m pip install -r requirements.txt
.\.venv311\Scripts\python.exe -m jarvis
```

Команды не требуют активации окружения или изменения ExecutionPolicy.
В VS Code: **Python: Select Interpreter → `.venv311\Scripts\python.exe`**.
Для следующих запусков достаточно последней команды из корня проекта.
Альтернатива ручной подготовке — `install.bat` (требует `py -3.11`).

### Через установщик

[Releases](https://github.com/BobLoTiK/jarvis-fenix/releases) → `Феникс_Setup.exe`,
если файл опубликован. Если его нет, используй исходники.
Лаунчер `Феникс.exe` подготавливает Python-окружение, зависимости и Vosk-модель;
это не автономная сборка со встроенным runtime. Первичная подготовка требует сети
и может занимать время. Для Piper установочный скрипт проверяет eSpeak NG.

В обновлённых исходниках подготовка проверяет VC++ x64 и при необходимости
предлагает официальный подписанный установщик Microsoft с явным согласием.
Клиент Flet готовится до запуска основного окна; ошибки доступны в том же мастере.
HTTPS использует certifi без отключения проверки TLS; явно заданные CA сохраняются.
Пока голос готовится в фоне, команда может ответить только текстом, без блокировки
следующей команды. После готовности голос работает со следующего ответа.
При CUDA-ошибке Whisper пробует ту же кэшированную модель на CPU, без скачивания
другой модели; при отказе остаётся только достаточно уверенный Vosk.
Эти исходные исправления требуют пересборки Setup и Windows-приёмки:
[пакет надёжности запуска](WINDOWS_STARTUP_RELIABILITY.md).

Обновление исходников не должно заменять личные файлы в `%APPDATA%\Phoenix`.
Перед обновлением закрой приложение; свои изменения в коде сохрани отдельно.

<a id="first-run"></a>
## 🚀 Первый запуск

1. Дождись подготовки моделей: набор загрузок зависит от включённых ASR/TTS-движков.
2. Во вкладке **Микрофон** выбери устройство и запусти тест на три секунды.
3. Проверь «Феникс, открой блокнот» голосом и через поле чата.
4. В **Голос и звук** выбери движок, голос и темп, затем нажми **Послушать голос**; в **Персоне** — стиль общения.
5. Для диалога настрой [Ollama](#ollama). Для быстрых команд она не нужна.

По умолчанию модели Vosk находятся в `C:\ProgramData\Phoenix\models`, Whisper —
в `C:\ProgramData\Phoenix\whisper-cache`, кэш Silero — в `C:\ProgramData\Phoenix\torch`.
Кэш Piper определяется его загрузчиком; не считай его папкой Whisper.
Пути и запасные варианты выбирает `jarvis/paths.py`, а не название checkout.
Личные настройки/профили обычно находятся в `%APPDATA%\Phoenix`.
Не перемещай Vosk-модель в путь с кириллицей.

<a id="onboarding"></a>
## 🎓 Знакомство (первый диалог)

**Никаких анкет.** Феникс **сам начинает живой диалог**:

> «Привет! Я Феникс, локальный голосовой помощник. Не хочешь немного поболтать? Расскажи — чем занимаешься, что нового?»

**Дальше — LLM ведёт диалог.** Слушает, отвечает, **если удобно** — спросит имя, стиль. **Не допрашивает.** Может завершить за 3–5 обменов или растянуть на 6+ (потом — принудительно).

**Хочешь сразу команды** — просто скажи **«Феникс, открой ютуб»**. Онбординг **пропустит команду**, откроет ютуб и **вернётся к знакомству**.

**LLM недоступна** — онбординг **молча завершается**. Никаких ошибок.

**Сброс:** «давай заново познакомимся» → `persona.reset_onboarding()`.

<a id="persona"></a>
## 🎭 Персона и стиль общения

Вкладка «Персона» разделяет имена, манеру общения и детали характера.
Изменения применяются кнопкой **«Сохранить персону»**; **«Отменить изменения»**
возвращает сохранённые значения. Черты можно добавлять и удалять чипами.
Незавершённая черта в поле добавления включается при сохранении.

Имя пользователя и персона сохраняются в **текущем профиле**, не глобально.
Смена темы/вкладки не теряет черновик; смена профиля не переносит его другому
пользователю. При конфликте или ошибке записи черновик остаётся, успех не показывается.
«Повторить знакомство…» требует подтверждения; факты и история не удаляются.
Портрет справа — иллюстрация стиля, не ответ LLM и не тест понимания.

**Персона хранится в `profile.json` → `persona`:**

~~~~json
{
  "assistant_name": "Феникс",
  "speech_style": "friendly",
  "tone": "auto",
  "traits": [],
  "backstory": "",
  "onboarding_done": true
}
~~~~

**Стили:**

| Стиль | Как общается |
|---|---|
| `formal` | На «вы», официально |
| `friendly` | На «ты», тепло (по умолчанию) |
| `sarcastic` | С сухим юмором |
| `brief` | Коротко, по делу |

**Тон (`tone`) — «планка» общения, задаётся вручную:**

| Тон | Что значит |
|---|---|
| `auto` | Подстраивается под собеседника (по умолчанию) |
| `polite` | Явно вежливый, без мата |
| `unrestricted` | Не стесняется, если юзер сам матерится |

**Команды:**

| Фраза | Что делает |
|---|---|
| «поменяй стиль на строгий» | → `formal` |
| «говори на ты» | → `friendly` |
| «какой у тебя стиль» | Опишет |
| «как тебя зовут» | Скажет имя ассистента |
| «давай заново познакомимся» | Сброс онбординга |
| «говори проще» | Тон → `auto` |
| «без цензуры» | Тон → `unrestricted` |
| «верни цензуру» | Тон → `polite` |
| «какой у тебя тон» | Опишет текущий тон |

**Как работает:** `brain._system_with_context()` собирает `CHAT_SYSTEM + persona.build_prompt_block() + mood.build_prompt_block() + learning.build_context()`. Стиль, тон и настроение **напрямую влияют** на ответы LLM.

<a id="mood"></a>
## 💗 Mood (эмоции в моменте)

**Persona = «кто я».** Стабильное.
**Mood = «как я реагирую сейчас».** Меняется.

**Состояния:**

| Состояние | Когда |
|---|---|
| `neutral` | по умолчанию |
| `happy` | похвала, благодарность |
| `excited` | радость, восторг |
| `annoyed` | грубость в адрес ассистента |
| `bored` | долгое молчание |
| `tired` | «устал», «спать хочу» |

**Что меняет:**

- **TTS** — `excited` +10%, `tired` -10% скорости.
- **GUI** — подпись настроения, отдельно от индикатора этапа обработки.
- **LLM** — блок в system prompt, отвечает с учётом настроения.

**Автоматически возвращается к `neutral`** через 5 минут.

**Команды:**

| Фраза | Что делает |
|---|---|
| «Как настроение» | описывает |
| «Не грусти» | `happy` |
| «Успокойся» | `neutral` |

Определение настроения и просодии — эвристики, не измерение эмоций человека.
Настройки влияют на стиль ответа, но не гарантируют поведение любой LLM.

<a id="observer"></a>
## 👁 Observer (фоновое обучение)

Observer извлекает явно сказанные сведения о пользователе в фоне.
**По умолчанию выключен**: Настройки → «Приватность и память» → «Запоминать факты из диалога».
Нажми «Применить изменения»; включение и отключение действуют после перезапуска.

Он периодически отправляет сообщения пользователя в настроенную LLM и пытается
сохранить прямые утверждения, например город или профессию. Ответы ассистента
не используются как факты; уже заполненные имя и город не перезаписываются.
Вопросы, цитаты и предположения не должны становиться фактами, но извлечение LLM
не гарантирует отсутствие ошибок. Проверяй сохранённые сведения.

Это сбор контекста, **не обучение весов**. При удалённом `ollama_url` выбранный
сервер получает анализируемый текст. Диагностика — `USER_DIR/logs/observer.log`.

<a id="memory-rag"></a>
## 🧠 Векторная память фактов (RAG)

Факты хранятся в профиле, производный индекс — в `memory_index.json` рядом с ним.
Сначала текущий запрос ограничивает допустимые сведения, затем RAG может
ранжировать их по смыслу. Ошибка или неуверенный поиск не разрешают подставить
весь профиль. Общая просьба рассказать что-нибудь не должна вызывать пересказ
личных данных.

**По умолчанию выключено.** Для включения установи модель эмбеддингов:

```powershell
ollama pull nomic-embed-text
```

Затем в Настройках нажми «Проверить подключение»: в выбранной Ollama должна
найтись настроенная embedding-модель. Включи «Подбирать факты по смыслу» и
нажми «Применить изменения». Экран не скачивает модель автоматически.
`memory_rag_model` по умолчанию — `nomic-embed-text`. Качество зависит от языка,
набора фактов и модели; косинусная оценка не является вероятностью правильного ответа.
При недоступности эмбеддингов используется ограниченный отбор по словам/запросу,
без передачи всех личных фактов. Это не удаляет сведения на диске.

«Что ты обо мне помнишь» показывает факты. «Забудь про работу» может находить
сведения по смыслу; проверь результат удаления. Локальность запросов зависит
от заданного `ollama_url`.

<a id="uia"></a>
## 🖥 UIA (управление окнами)

**UIA** (UI Automation) — Windows-технология, которая позволяет Фениксу **видеть структуру** окон: вкладки, кнопки, поля.

**Что умеет:**

| Фраза | Что делает |
|---|---|
| «Что открыто» | описывает активное окно |
| «Прочитай окно» | читает текст активного окна |
| «Какой сайт открыт» | URL или заголовок активной вкладки |
| «Какая вкладка» | заголовок активной вкладки |
| «Какие вкладки» | список всех вкладок |
| «Закрой вкладку ютуб» | закрывает **только эту вкладку** (с проверкой, что она правда закрылась) |
| «Переключись на вкладку хабр» | активирует |
| «Нажми OK» | нажимает кнопку по имени |

**Работает** в Chrome, Edge, Firefox, Opera, Brave, Яндекс.Браузере, Vivaldi, Arc и других (20+).

**Особенности:**

- **URL** Яндекс.Браузер не отдаёт через UIA — используется заголовок окна. Chrome/Edge отдают.
- **Вкладки** читаются у всех Chromium-браузеров (18+ за раз).
- **Закрытие вкладки** проверяется по списку вкладок: браузер отдаёт «успех»
  даже когда кнопка закрытия нажата впустую, поэтому Феникс пробует три
  способа (кнопка → средний клик по вкладке → выбор вкладки + Ctrl+W) и
  говорит «закрыл» только если вкладок стало меньше.
- Библиотеки `uiautomation` может не быть (например, на CI). Тогда UIA-команды
  отвечают «UI Automation недоступна: не установлена библиотека uiautomation.
  Установите её: `pip install uiautomation`» — Феникс не падает и не уходит
  в LLM. Ветки без UIA («нажми enter», «закрой вкладку эту» — Ctrl+W)
  могут работать без чтения дерева UIA; результат зависит от активного окна.

**Что не умеет:**

- Читать картинки (это VLM-зрение, в планах).
- Работать в играх (DirectX/Unity не регистрируют элементы).
- Взаимодействовать с canvas-приложениями (Figma, Photoshop частично).

<a id="troubleshooting"></a>
## ⚠️ Возможные проблемы

| Симптом | Что проверить |
|---|---|
| Ошибка нативной DLL | Python 3.11, окружение `.venv311`, VC++ Redistributable x64; полный traceback. |
| Vosk не загружается | ASCII-путь модели и права доступа; фактический путь из `paths.py`. Не считай любой DLL-crash уже решённым. |
| Не загружается Whisper | В обновлённых исходниках ImportError/OSError при предзагрузке переводит текущий запуск на Vosk; конфиг не меняется. Для Windows проверь официальный VC++ Runtime x64, загрузку модели, диск и кэш. [Подробности и старые сборки](WHISPER_STARTUP_DLL_FIX.md). |
| Микрофон молчит | Разрешения Windows, выбранное устройство и тест во вкладке «Микрофон». |
| Команда искажена | Сравни голос и чат, спроси «что ты слышал» / «почему не понял», уменьши фоновый шум. |
| Нет разговора | `ollama list`, точный тег, `ollama_url`, доступность сервера и режим ИИ/Комбо. |
| Нет окна | Запусти из терминала; проверь `launch_mode`, `gui_enabled` и [логи](#logs). |
| Нет реакций в голосе | Они выключены по умолчанию; SAPI их не поддерживает. См. [реакции](#nonverbal). |
| UIA не видит приложение | Доступность его элементов, библиотека `uiautomation`; canvas/игры могут не иметь нужного дерева. |
| Кириллица испортилась | UTF-8 без BOM, CRLF; не перекодируй весь проект случайной командой. |

Не удаляй `profiles` и личный конфиг как первый способ починки.
В сообщении об ошибке приложи версии Windows/Python, способ запуска,
действие для воспроизведения и небольшой фрагмент лога без личных данных.
Проблемы сборки тестов и проверок — в [CI.md](../CI.md).

<a id="gui"></a>
## 🖼 GUI (Flet)

- При запуске окна открывается минималистичная «Главная»: птица, местные дата
  и время, короткий статус. Строка сообщения остаётся в Диалоге;
  карточки можно добавить самому через «+ Виджеты».
  Переключатель «Сумерки / Фарфор» меняет общую тему приложения.
  В покое корона постоянно и медленно движется, как тихое солнце.
  Входящий звук усиливает свечение и добавляет расходящиеся волны, а речь
  Феникса — ещё один огненный контур и больше небольших искр.
  Режимы плавно перетекают: свечение, амплитуда, волны и искры нарастают
  постепенно; спад мягче включения. При быстрой смене состояний движение
  не начинается заново. Шум тоже может
  вызвать реакцию: это не подтверждение распознанной речи. При обработке
  корона движется спокойнее. На других вкладках и в скрытом окне эффекты
  не крутятся. `gui_motion_enabled: false` отключает движение; системное
  уменьшение движения учитывается, если его сообщает Flet.
- «Диалог» — отдельный второй пункт: там находятся переписка, поле ввода,
  режим работы, голос и история. Возврат на Главную не очищает диалог/черновик.
- Боковая панель: Главная / Диалог / Микрофон / Голос и звук / Персона / Настройки / Мои команды.
  Внизу — название текущего профиля, без выдуманного индикатора подключения.
- Панель свёрнута до иконок (76 px), раскрывается по наведению (252 px).
  На любой ширине окна содержимое плавно уступает ей место за 200 мс.
  Даже в узком окне панель не перекрывает заголовки, поля и кнопки.
  После ухода курсора сворачивается с задержкой.
  Булавка закрепляет панель и выделяет ей место; выбор сохраняется после перезапуска.
  В небольшом окне пункты меню прокручиваются, булавка и профиль остаются снизу.
- Наведение: близкая к выбранному пункту заливка, небольшое увеличение иконки
  и один медный блик по рамке. Tab раскрывает панель при фокусе, Escape
  сворачивает незакреплённую. Системное уменьшение анимации учитывается, если
  платформа сообщает его Flet; ручное отключение — `gui_motion_enabled: false`
  в `config.json` при полностью закрытом приложении.
- Тёмная тема «Сумерки» и светлая «Тёплый фарфор»; знак птицы меняет обводку
  по этапу обработки, не изображает измерение микрофона.
- Компактный индикатор этапа: готов / слушаю / распознаю / обрабатываю / говорю,
  ожидание уточнения или пароля и ошибка. Цвет не заменяет текст статуса.
- Карточки сообщений с выделяемым текстом и кнопкой копирования.
- Режим, голос и объём истории — над панелью ввода. Подпись модели показывает
  настроенный тег, а не доступность Ollama; в режиме команд указано «без LLM».
- Enter отправляет сообщение, Shift+Enter добавляет строку. Пока GUI-запрос
  выполняется, повторная отправка недоступна; можно продолжать писать черновик.
- Стоп доступен во время ответа: останавливает озвучку, но не отменяет
  действие ОС, запрос к модели или генерацию. Не означает «откатить команду».
- Если прокрутить чат вверх, новые сообщения не должны уводить вниз;
  «К последнему сообщению» возвращает автоследование.
- Смена темы/списка голосов сохраняет обычный черновик и активный стрим,
  перерисовывает сообщения новой палитрой. Парольный черновик не сохраняется.
- Три карточки пустого чата подставляют «Поставь таймер», «Открой» или
  «Расскажи что-нибудь». Затем допиши запрос и нажми Enter; сами карточки ничего
  не исполняют и не меняют скрытое парольное поле. Доступны с клавиатуры.
- Ошибка обработки показана в блоке на Главной; повторного исполнения без
  пользователя нет. Перед повтором проверь, не успело ли действие выполниться.
- Настройки: LLM/URL, проверка наличия моделей, приватность, тема, трей и запуск.
  Кнопка проверки не запускает LLM и ничего не скачивает. При изменении адреса
  результат прежней проверки становится недействительным. Удалённый адрес означает
  передачу запросов выбранному серверу; HTTP/HTTPS без credentials/query/fragment.
- «Применить изменения» сохраняет поля Настроек одним пакетом; тема применяется
  сразу и не откатывается кнопкой отмены. Конфликт или ошибка записи показаны явно.
  Observer и режим старта требуют перезапуска; остальные поля — после сохранения.
- Микрофон: выбор/обновление устройств, свежий уровень и трёхсекундная проверка.
- Голос и звук: TTS, голос, темп, безопасная проба, реакции и расширенные настройки распознавания.
- Персона: имена, стиль/тон, черты, контекст, портрет-пример и подтверждаемый сброс знакомства.

**Режим запуска:** `"launch_mode": "gui"` — окно при старте, `"tray"` —
только трей (окно скрыто). Выбирается во вкладке «Настройки», применяется
после перезапуска.

| Параметр | Что делает |
|---|---|
| `"gui_enabled": false` | Отключить GUI |
| `"tray_enabled": false` | Отключить трей (переключатель «Оставаться в трее», после «Применить изменения») |
| `"vad_auto_download": false` | Не качать модель Silero VAD (2.3 МБ) — для машин без сети |

<a id="ollama"></a>
## 🧠 Настройка LLM (Ollama)

Установи [Ollama](https://ollama.com/download) и загрузи модель:

```powershell
ollama pull qwen2.5:7b-instruct
ollama list
```

Укажи в настройках точный тег из `ollama list`. Значения по умолчанию:

```json
{
  "llm_model": "qwen2.5:7b-instruct",
  "use_llm": true,
  "ollama_url": "http://127.0.0.1:11434"
}
```

Это фрагмент настроек, не команда для перезаписи всего конфига.
Если сервер не запущен, проверь приложение Ollama; при необходимости — `ollama serve`.
Модель можно сменить, например выбрать меньшую под доступную память. Размер,
квантизация, контекст и железо влияют на скорость и потребление памяти;
одинаковое качество разных моделей не гарантируется.

Профили и факты приложения не принадлежат весам выбранной LLM и не исчезают
из-за её смены. Запоминание и исправления в Фениксе — не LoRA и не дообучение модели.

<a id="numbers"></a>
## 🔢 Числа и чтение текста

Феникс разбирает числа словами в командах громкости, яркости, длительности и времени.
Дробная запятая и двоеточие времени сохраняются до разбора; неоднозначное значение
требует уточнения, а не догадки. Произвольный текст задачи и пароли не переписываются.

Для озвучки используется общий языковой слой с русской морфологией: числительные,
контекстные римские цифры и единицы измерения. Например, «в XXI веке» читается
«в двадцать первом веке». Прямая и потоковая озвучка используют одинаковую подготовку.

<a id="nonverbal"></a>
## 🎭 Звуковые реакции

Смех, вздох, «хм» и зевок делают диалог живее — без случайных звуков в командах,
запросах пароля, напоминаниях и уточнениях.

**Включение:** вкладка **Голос и звук → Звуковые реакции**. По умолчанию выключено;
переключатель применяется сразу. Работает с **Silero, Piper и WinRT**, включая
потоковый ответ. **SAPI** говорит без реакций.

Реакция выбирается по текущему настроению с учётом настроенной политики просодии.
Максимум одна попытка на ответ; по умолчанию вероятность 20%, пауза минимум
45 секунд и уровень −15 дБ относительно RMS речи. Это не звук на каждую фразу.
Речь и реакция выводятся одним PCM-потоком и вместе прерываются barge-in.

| Настройка | По умолчанию | Диапазон |
|---|---|---|
| `nonverbal_enabled` | `false` | включатель во вкладке «Голос и звук» |
| `nonverbal_cooldown_sec` | `45.0` | 10–3600 секунд |
| `nonverbal_gain_db` | `-15.0` | −18…−12 дБ |
| `nonverbal_probability` | `0.2` | 0–1 |

Параметры приведены в `config.example.json`. Четыре записи входят в установщик;
во время диалога ничего не скачивается. Пропал/повреждён сэмпл — остаётся обычная речь.
Тембр фиксированных записей может отличаться от выбранного голоса. Кашель отложен.
[Источники и лицензии сэмплов, ручное прослушивание](../assets/nonverbal/README.md).

<a id="voices"></a>
## 🎙 Голоса

Движок выбирается через `"tts_backend"` (`auto` → Silero → Piper → WinRT → SAPI).

| Движок | Голоса |
|---|---|
| Silero | `aidar`, `baya`, `kseniya`, `xenia`, `eugene` |
| Piper | `ruslan`, `dmitri`, `irina`, `denis` |
| WinRT | `Pavel`, `Irina` |
| SAPI | зависит от системы |

- «смени голос на Ирину» / «какой голос» / «какие голоса».
- Во вкладке **Голос и звук** — движок, голос, скорость и **Послушать голос**.
  Быстрый выбор голоса также остаётся в «Диалоге».
- Проба произносит фиксированную фразу через обычный Jarvis.say/Speaker, без
  LLM, записи в чат, память и без звуковых реакций. Стоп останавливает речь.
- Проба не встаёт в очередь за командой, не прерывает текущую речь и не запускается
  при ожидании пароля/уточнения. Повторные клики не создают новые потоки.
- Подпись показывает загруженный движок, а не обещание слышимого звука. Список
  голосов может содержать запасные варианты; модели должны быть установлены.
  «Проба завершена» не подтверждает выход на физические колонки.
- Nonverbal и Prosody — в блоке «Живое звучание». VAD, паузы Vosk, обращение и
  barge-in — в раскрывающемся блоке «Распознавание и фильтр тишины».

Настройки голоса зависят от движка; список доступных системных голосов — от установки Windows.

<a id="barge-in"></a>
## ✋ Barge-in (перебивание)

`barge_enabled: true` включает возможность прервать озвучку голосом.
Используются окно защиты от собственного эха и порог относительно уровня сигнала.
Результат зависит от колонок, помещения и микрофона: проверь на своём устройстве.
Голос и звуковая реакция используют общий stop-token и должны прекращаться вместе.
Автоматический аудиопрогон не проверяет реальное эхо и перебивание.

<a id="microphone"></a>
## 🎤 Микрофон

Вкладка «Микрофон»:

- Выбор устройства с полным именем, обновление списка и отображение текущего
  входа. Изменение применяется без перезапуска; Listener сам переоткрывает поток.
  Сохранённый, но отсутствующий вход не заменяется молча в настройках.
- Живой RMS и условная шкала: 100% соответствует RMS 2000, это не системная
  громкость и не оценка качества распознавания. Старый пик не означает, что
  микрофон слышит сейчас; без свежих callback-данных шкала очищается.
- **Проверить уровень · 3 сек** собирает свежие RMS-показания текущего Listener.
  Максимум за окно ≥500 — заметный сигнал, ≥100 — тихий; ниже — заметного сигнала
  нет. Это эвристика, шум также способен пройти такую проверку.
- Проверка не открывает второй аудиопоток и не сбрасывает peak/utterances.
  Смена входа, пауза или mute во время проверки делают результат недействительным.
- Обычное распознавание во время замера остаётся включённым: говори без обращения.
  Если ожидание wake-слова отключено, любая распознанная речь может стать командой.
- RMS не выдаётся за «эмоцию». Интонация отдельно оценивается Prosody,
  с явной пометкой о приблизительном характере эвристики.

`mic_watchdog` проверяет стартовую тишину только для журнала: без озвучки
«Я не слышу микрофон» и без автоматического открытия вкладки. Ручная проверка
уровня и сообщения о настоящем сбое аудиопотока сохранены.

Перед выполнением команды проверяются сигнал, уверенность слов Vosk и сегментов
Whisper. При сомнении Феникс просит повторить, не выполняя и не сохраняя догадку.
Расхождения в числах, отрицании и поддержанных командных действиях требуют уточнения.
Проверки не гарантируют безошибочное ASR и не заменяют настройку микрофона.

<a id="audio-tests"></a>
## 🎧 Автоматическая проверка голоса

Из активной `.venv311`, в корне проекта:

```powershell
python scripts/audio_regression.py prepare
python scripts/audio_regression.py run
```

`prepare` один раз создаёт локальные WAV русским системным голосом Windows.
`run` переигрывает их через настоящий VAD → Vosk → Whisper → ASR-gate →
обработчик команд. Открытие приложений и создание таймеров заменены безопасным
журналом в памяти: ничего не запускается и не записывается в профиль.
По умолчанию — 27 кейсов / 51 аудиоход: уточнения, исправление времени,
отмена, отсутствие обращения, тишина и шум; чистый, тихий и зашумлённый варианты.

Модели должны быть установлены локально. При их отсутствии — `BLOCKED`, код 2,
не фиктивный успех. Модели не скачиваются. `--asr vosk` / `--no-vad` — явно
сокращённые диагностические профили. WAV и отчёты по умолчанию остаются в
`USER_DIR/audio-regression`, вне исходников. Повторно синтезировать их перед
каждым запуском не нужно; после изменения сценариев нужен новый `prepare`.

Это регрессия ограниченного командного контура, не полная проверка приложения:
микрофон, эхо, barge-in, звучание TTS, GUI, опасные команды и LLM не измеряются.
Можно подставить собственные записи вместо синтеза. Подробности, пути моделей,
коды завершения и границы измерений — [tests/audio/README.md](../tests/audio/README.md).

<a id="clarifications"></a>
## 💬 Уточнения команд

Феникс может запросить недостающий параметр без обращения к LLM:

| Ты | Феникс | Ответ |
|---|---|---|
| «Открой» | Какое приложение открыть? | «Блокнот» |
| «Поставь таймер» | На сколько или в какое время? | «На пятнадцать минут» |
| «Напомни выпить чай» | На сколько или в какое время? | «Через пять минут» |
| «Поставь таймер на десять» | В каких единицах? | «Минут» |

В ответе можно поправиться до выполнения: «на десять… нет, на пятнадцать минут».
Для приложения требуется точное известное имя/алиас, название ярлыка или игры;
непонятный ответ не превращается в угаданный сайт.
«Отмена», «отмени», «не надо» сбрасывают ожидание. Ожидание одно, срок — 30 с;
после трёх непонятных ответов действие отменяется. Новая поддержанная команда
заменяет ожидание. Голосом в этом окне можно отвечать без повторного обращения.
Если составная команда остановилась на вопросе, её оставшиеся части не продолжатся автоматически.

Это первый ограниченный набор слотов, не универсальное понимание любой недоговорённой
фразы. «Нет, на пятнадцать» ПОСЛЕ создания таймера пока не изменяет готовый таймер.
Новые связи автоматически не запоминаются; подтверждаемое самообучение — следующий этап.

Для диагностики скажи «покажи время обработки»: предыдущая обработка и до трёх
самых долгих стадий, без времени распознавания, генерации потокового ответа и озвучки.

<a id="custom-commands"></a>
## 🛠 Свои команды

### Конструктор в GUI

**Мои команды → Новая команда** объединяет короткие фразы-смыслы и сценарии.
Одна фраза может означать одно действие или последовательность до шести шагов.
Примеры в разделе только заполняют редактор: не сохраняют и не исполняют команду.

1. Укажи название и 1–12 фраз (каждая с новой строки). Обращение «Феникс»
   писать необязательно; регистр/пунктуация/ё нормализуются. Совпадение точное,
   без нечёткой подстановки. «Отмена» и отмена выключения зарезервированы.
2. Выбери действия и фиксированные параметры: приложение по названию из меню Пуск,
   полный HTTP(S)-адрес сайта, громкость 0–100%, таймер 1–86400 секунд, музыка,
   скриншот, текст ответа, выключение/перезагрузка или отмена выключения.
3. Добавь, переставь или удали шаги. Выключение/перезагрузка — только последним
   шагом, с задержкой 10–600 секунд. Произвольных shell-строк в редакторе нет.
4. **Проверить фразу** проверяет текущий черновик тем же чистым matcher, но не
   вызывает handler, TTS и действия ОС. Это не проверка ASR, установленного
   приложения, сайта или успешного выполнения сценария.
5. **Сохранить команду** записывает custom_commands в пользовательский config.json
   атомарно; живой handler обновляется без перезапуска. Само сохранение ничего
   не исполняет. Команды общие для профилей. Есть включение/выключение,
   редактирование и удаление с подтверждением.

**«Спокойной ночи» → выключение ПК:** открой соответствующий пример, выбери
задержку (по умолчанию 30 секунд), в блоке «Защита системных действий» задай
и повтори пароль, затем сохрани команду. При обращении «Феникс, спокойной ночи»
сначала запрашивается пароль. Без настроенного пароля системное действие
не выполнится — то же правило действует и для «удали профиль X»: удаление
профиля необратимо, поэтому без пароля Феникс откажет, а не удалит молча.
Проверяется весь сценарий **до первого шага**; неверный пароль
или «отмена» не выполняют даже предыдущие безобидные шаги.
После успешного ввода пароля отмена запланированного выключения — отдельная
фраза **«отмени выключение»**, работает без активации system-пака. Успех операции подтверждается кодом возврата Windows; отсутствие запланированного
выключения не выдаётся за успешную отмену. Обычный Stop
озвучки не отменяет выключение и другие системные действия.

Пароль задаётся/заменяется штатным SHA-256-механизмом, не хранится в сценарии
или черновике и не выводится в историю. При пересборке темы парольные поля пустые;
обычный черновик сценария сохраняется. Незавершённые правки при «К списку» или
«Новая команда» отбрасываются, переход между вкладками их не теряет.

Параметры пока **фиксированные**, не переменные вида «сделай X на {значение}».
Не назначай фразы встроенных команд: более ранние стадии pipeline (отмена,
слоты, onboarding, память, режимы и составные команды) могут иметь приоритет.
Сценарий выполняется последовательно существующим executor; это не транзакция,
успешные предыдущие действия не откатываются при дальнейшей ошибке.

### Старый формат и паки

Ранее заданные команды не перезаписываются и показываются только для чтения;
их по-прежнему можно менять в config.json. Нечёткий поиск старого формата
сохранён, но точное совпадение в общем списке имеет приоритет.
Паки не копируются в пользовательский список при горячем обновлении.

Свои команды хранятся в настройках пользователя. Формат старой записи:

```json
{
  "phrases": ["открой документы"],
  "action": "C:\\Users\\Public\\Documents",
  "reply": "Открываю документы."
}
```

Поддерживаются пути, URL, `open_app:discord`, `browser`, `steam://` и макросы
`{"steps": [...]}`. Команды с аргументами исполняются через subprocess.
Проверка опасности должна происходить до первого шага макроса, но это не песочница:
не импортируй неизвестные команды/паки и не запускай непроверенные shell-строки.
Используй GUI и текущий формат [config.example.json](../config.example.json),
а не замену всего личного `config.json` примером из документации.

<a id="build"></a>
## 📦 Сборка `.exe` и установщик

Одна команда собирает всё: иконку, баннеры, `.exe` и установщик.

~~~~bat
python scripts\build_setup.py --check            REM ресурсы, без компиляции
python scripts\build_setup.py
python scripts\build_setup.py --run              REM + сразу запустить установщик
python scripts\build_setup.py --version 1.0.2   REM версия установщика
~~~~

**Что делает `build_setup.py`:**

| Шаг | Действие |
|---|---|
| 1 | `scripts\make_icon.py` — `jarvis\icon.ico` (из актуального бренд-ресурса) |
| 2 | `scripts\make_installer_images.py` — BMP-баннеры для Inno Setup |
| 3 | `scripts\build_exe.py` — `Феникс.exe` (PyInstaller) |
| 4 | `scripts/release_payload.py` — чистая поставка и SHA-256 manifest |
| 5 | `ISCC.exe installer.iss` — `dist\Феникс_Setup.exe` |

**Требуется:** PyInstaller (в `requirements-dev.txt`), Pillow и Inno Setup 6
([скачать](https://jrsoftware.org/isdl.php)). `ISCC.exe` ищется через `INNO_SETUP` (путь к EXE или папке), затем `PATH` и стандартные папки Inno Setup 6.

Диагностика `system_caps.json` создаётся на компьютере пользователя в `%APPDATA%\Phoenix`, не на машине сборщика. Состав поставки и проверка обновления — [INSTALLER_UPDATE.md](INSTALLER_UPDATE.md).

**Версия** берётся из `installer.iss` (`MyAppVersion`), а `--version`
переопределяет её на лету (в ISCC уходит `/DMyAppVersion`). CI подставляет
версию из тега: `git tag v1.0.2` → установщик с версией `1.0.2`.

**Авторелиз.** Пуш тега `v*` запускает
[`.github/workflows/release.yml`](../.github/workflows/release.yml): он собирает
`Феникс.exe` + `Феникс_Setup.exe` на Windows-раннере и создаёт GitHub Release
с обоими файлами. Ручной запуск (Actions → **build-release** → Run workflow)
собирает то же, но без релиза — файлы остаются в артефактах запуска.

**Что кладёт установщик** — в `C:\ProgramData\Phoenix`:

| Что | Примечание |
|---|---|
| `Феникс.exe`, `jarvis\` | код (`__pycache__` и `*.pyc` исключены) |
| `packs\`, `scripts\` | паки команд и скрипты |
| `config.example.json`, `requirements.txt` | шаблон конфига + зависимости |
| `system_caps.json` | кэш возможностей (`actions.py`, `gui.py`) |
| `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md`, `LICENSE` | документация |
| `models\`, `runtime\` | пустые: Vosk-модель качает лаунчер |

**Обновление поверх старой версии:** `.venv311`, `models\` и данные в
`%APPDATA%\Phoenix` (`config.json`, `profiles\`, `logs\`) **не трогаются** —
Inno перезаписывает только код. Запущенного Феникса установщик попросит
закрыть (общий мьютекс с `launcher.py`).

**Что делает `make_installer_images.py`:**

| Файл | Размер | Назначение |
|---|---|---|
| `installer_banner.bmp` | 164×314 | Вертикальный баннер установщика |
| `installer_small.bmp` | 55×55 | Маленькая иконка вверху справа |

Лаунчер не содержит автономный Python-runtime. Это описание состава текущего
установщика: новые руководства и README-обложка доступны в репозитории; их
наличие в установленной папке зависит от списка файлов `installer.iss`.

## Действия вокруг Феникса на Главной

Наведи на центральную птицу — появятся Диалог, микрофон и остановка речи.
Переводи курсор к кнопкам: меню остаётся раскрытым. Уйди за окружение — оно
мягко исчезнет. Названия показываются под кольцом. Диалог открывается отдельно;
микрофон ставится на паузу/возвращается, остановка озвучки доступна во время
речи. Она не отменяет выполненные команды и не прерывает сетевую генерацию.
С клавиатуры: Tab до птицы (или Enter/Space на ней), затем Tab по действиям;
Escape закрывает кольцо. Без готового ядра аудиокнопки недоступны.

## Виджеты Главной
«+ Виджеты» → Задачи / Быстрые действия → «Сохранить». Карточки можно убрать,
переставить ручкой/стрелками и расширить. Отмена не меняет сохранённую раскладку.
Задачи — тот же общий локальный список, что у голосовых команд; отметки обратимы.
Быстрые действия запускаются только после сохранения и явного нажатия, через
Диалог и его обычные проверки. Удаление карточки данные не удаляет.
Подробнее: [установка и приёмка](GUI_WIDGETS_UPDATE.md).
Локальная озвучка/клон: [варианты следующего этапа](LOCAL_VOICE_OPTIONS.md).

## Подготовка приложения: изменения после 2.1.0
