# Общее обновление подготовки: Python HTTPS + выбор модели Ollama

## Применение одним архивом

Содержимое ZIP скопировать **прямо в C:\jarvis**, где лежат launcher.py и папка
jarvis. Заменить одноимённые файлы, объединить scripts/tests/docs/.github.
Предыдущий архив Python отдельно применять не требуется: его изменения включены.
Личных config.json, профилей, истории, моделей и окружений в архиве нет.

Это исходники. **Старый Феникс.exe содержит старый код внутри**: новые .py рядом
с установленным EXE его не обновят. Для результата в Sandbox нужна пересборка:

1. Обновить свой Git-репозиторий этими файлами, включая .github/workflows/release.yml.
2. Actions → build-release → Run workflow → скачать свежий Artifacts.
3. Сохранить логи старой песочницы наружу, закрыть её и открыть новую.
4. Перенести только свежий Феникс_Setup.exe и повторить чистую установку.

Ручной workflow не создаёт публичный Release. Опубликованный v2.1.0 не двигать;
публичные исправления выпускать новой patch-версией. Здесь EXE/Setup не собраны.

Локальная сборка на Windows с Python 3.11.9/.venv311, build dependencies и Inno 6:

```powershell
.\.venv311\Scripts\python.exe scripts/build_setup.py --check
.\.venv311\Scripts\python.exe scripts/build_setup.py
```

## 1. Python — исправление HTTPS-bootstrap

В пользовательской Sandbox urllib frozen-лаунчера получил отказ сертификата.
PowerShell в той же среде скачал официальный Python 3.11.9 x64, подпись Valid,
Python Software Foundation. После ручной подготовки Python старая установка
дошла до предложения Ollama. Это НЕ проверка нового патча и ещё не приёмка GUI.

Новый загрузчик использует Windows HTTPS/TLS 1.2 и обязательную проверку подписи
после скачивания и перед запуском. Не отключает SSL, не устанавливает корневые
сертификаты. Незавершённые/непроверенные EXE не запускаются; временные файлы
разделены по попыткам и очищаются. Подробности: PYTHON_BOOTSTRAP_TLS_FIX.md.
Vosk/pip не переводились на другой транспорт этим патчем.

## 2. Ollama и модель — в том же окне подготовки

- Если Ollama отсутствует: явное предложение открыть официальный сайт.
  Сам официальный установщик Ollama пользователь устанавливает отдельно;
  его EXE не скачивается/не запускается молча этим патчем.
- Затем «Проверить» в том же окне. При наличии ollama.exe запускается serve и
  ожидается готовность API; наличие процесса не считается готовностью.
- Если текущая модель уже есть локально — никаких новых загрузок и замен.
- Если модели нет — выпадающий список с уже скачанными локальными моделями и
  тремя вариантами Qwen2.5 Instruct: 1.5B (~986 МБ), 3B (~1,9 ГБ), 7B (~4,7 ГБ).
  Это примерные размеры файлов, не оценка RAM, скорости или качества.
  Каталог выбран как варианты уже используемого семейства, не как бенчмарк.
- Просмотр списка не запускает загрузку. Нужна кнопка «Скачать и использовать»
  либо «Использовать модель» для уже скачанного варианта. Тянется только выбранная.
- Загрузка через локальный POST /api/pull с stream=true, insecure=false.
  Отображается реальный прогресс текущего слоя, не выдуманный общий процент.
- После success проверяются /api/tags и /api/show: наличие модели, локальность и
  поддержка completion. Embedding-only модели не сохраняются как модель диалога.
  Это проверки метаданных/наличия, **не тест генерации или качества**.
- После проверки сохраняется только llm_model. ollama_url/mode/голос/профили
  не меняются. Другие настройки сохраняются; конфликт model/url/mode за время
  загрузки приводит к отказу записи, а не молчаливому перетиранию.
- Запись идёт через установленную .venv311 и штатные paths/config_manager,
  под существующим FileLock с атомарной заменой. Frozen launcher не импортирует
  runtime/audio/config и не требует новых Python-пакетов; filelock уже есть у проекта.
- Повреждённый config не перезаписывается мастером. Нестандартный/удалённый
  endpoint не опрашивается этим локальным мастером и не заменяется localhost.
- API-запросы мастера ограничены HTTP loopback, обходят внешние proxy и не
  следуют редиректам. Облачные модели и произвольные pull-теги не предлагаются.
- «Продолжить без ИИ» до этапа загрузки ничего не скачивает и не меняет выбор.
  Это пропуск настройки, не принудительная запись mode=commands. При явно
  заданном режиме commands весь мастер ИИ пропускается.
- Ошибка загрузки/подтверждения/записи: повторить либо продолжить без настройки.
  Нет бесконечного автоматического retry. При активной загрузке, как и раньше
  при pip/установке, закрытие не прерывает этап; отказ доступен до его начала.
  HTTP inactivity timeout 30 с, проверка общего срока между событиями — 2 часа.

Модели хранятся и скачиваются самой Ollama, не копируются в проект/ZIP и не
навязываются автоматически по GPU/RAM автора. У моделей свои лицензии.

```powershell
.\.venv311\Scripts\python.exe -m pytest tests/test_launcher_download.py tests/test_launcher_ollama.py tests/test_bootstrap_ollama_config.py tests/test_launcher_ui.py tests/test_build_setup.py tests/test_release_payload.py -q

.\.venv311\Scripts\python.exe snapshot.py --check
```

При подготовке: **149 passed, 2 skipped**, Linux/Python 3.13. Среди проверок:
настоящий loopback HTTP-сервер (/tags, NDJSON pull, /show, ошибки, redirect,
частичный прогресс), настоящий subprocess в отдельном venv для config bridge,
реальные временные JSON/atomic writes, конфликты настроек, пропуски/повтор,
контракт очереди и mocked Tk-контролов. Нет скачивания весов или inference.

В этом стенде нет Tk/Windows GUI. Выпадающий список визуально не принят.
Пропуски: настоящий Windows PowerShell для unsigned EXE и opt-in live Python
скачивание. Release workflow запускает регрессии на Windows до сборки;
там для config bridge tests дополнительно установлен существующий filelock.
Обычный pytest не скачивает модели или Python и не ставит Ollama.
Полный check_all, Windows EXE/Setup, GPU/аудио и inference здесь не проверены.

## Чистая Windows-приёмка

- Python скачивается, подпись проходит, официальный installer открывается.
- После установки Ollama «Проверить» продолжает мастер, а не закрывает его
  сразу после открытия сайта.
- Варианты моделей видны, размер и запрос согласия понятны; CPU/GPU-обещаний нет.
- Проверить отдельно: пропуск, выбор существующей модели, загрузку одной новой,
  обрыв сети и повтор, повторный запуск без лишней загрузки, сохранность профиля.
- После выбора проверить llm_model через Настройки Феникса и сам диалог вручную.
  Наличие /tags не доказывает способность ПК загрузить модель в память.
- Журналы сохранить наружу до закрытия Sandbox. Текущий старый установщик можно
  продолжать проверять отдельно; его результаты не переносить на новую сборку.
