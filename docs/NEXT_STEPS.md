# Дальнейшие действия после 2.1.0

## Текущий блокер и дополненный бэклог

Ярлык установленного Феникса не открывает приложение; причина без целевого
launcher.log не установлена. Сначала исправление/диагностика запуска, затем
Windows-сборка и приёмка. Новые улучшения и критерии:
[IMPROVEMENT_BACKLOG.md](IMPROVEMENT_BACKLOG.md).
Если v2.1.0 уже опубликован, исправления выпускать новым patch-тегом.

## 0. Выпустить и проверить 2.1.0

- [ ] Скопировать обновление в настоящий Git-репозиторий, проверить diff и состав staged-файлов. Не коммитить config.json, профили, историю, логи, модели, venv и секреты.
- [ ] Запустить Windows `check_all.py`, `snapshot.py --check` и `scripts/build_setup.py --check`.
- [ ] Закоммитить изменения; создать annotated tag `v2.1.0` на этом коммите и отправить его. Не переставлять уже опубликованный тег; для исправлений — новая patch-версия.
- [ ] Проверить зелёный build-release и наличие EXE/Setup. Workflow берёт заметки из `docs/releases/v2.1.0.md`.
- [ ] Smoke-test чистой установки и обновления: пользовательские данные сохранены, окно/трей/повторный запуск, отсутствие вспышки Flet, обе темы, панель со сдвигом, виджеты и звук.

Без Windows smoke-test не считать стабильность установки подтверждённой. Тесты на Linux не заменяют эту приёмку.

## 1. Ближайшая patch-версия: только реальные регрессии

- [ ] Зафиксировать найденные сбои запуска/трея/GUI и покрыть воспроизводимыми тестами.
- [ ] Проверить скорость Silero: параметр читается, но в прежнем аудите не было подтверждено его применение к реальному синтезу/PCM. Исправить или честно ограничить UI; не менять темп подменой sample rate с изменением высоты голоса.
- [ ] Проверить stop/barge-in в состояниях генерации, синтеза, проигрывания и ожидания уточнения. Не должно быть запоздалой речи, команд или старого ответа после отмены.

## 2. Следующий функциональный этап: лёгкая локальная озвучка

1. **Baseline:** времена первого LLM chunk, безопасной фразы, готового PCM и начала звука, паузы, CPU/RAM. Измерять отдельно GUI, STT, LLM и TTS на нескольких конфигурациях Windows.
2. **Лёгкий пакет Piper:** явная установка модели/лицензии/размер, один активный голос, управляемое число CPU-потоков, понятный fallback. Не предполагать GPU или наличие голоса Windows.
3. **Настоящее перекрытие:** Ollama продолжает генерацию, пока готовые фразы синтезируются/звучат; маленький ограниченный буфер, порядок и backpressure. Сначала проверить блокировки существующего speak_stream.
4. **Отмена:** один stop-token на ответ, очищение непроговорённой очереди, отсутствие zombie-worker и одновременных плееров.
5. Сохранить safety/finalize_stream, историю, cmd_lock/_say_lock и общий PCM для звуковых реакций. Модель/параметры Ollama и голос пользователя не менять молча.

**Критерий:** первая речь до конца длинного ответа, нет потери/перестановки фраз, корректная отмена и измеримый выигрыш на целевых ПК без искусственного ожидания полного ответа. Конкретные бюджеты задержки/нагрузки задаются после baseline, не на глаз.

## 3. Надёжность повседневной работы

- [ ] Отключение/возврат микрофона, смена устройства, сон/пробуждение Windows.
- [ ] Ollama недоступна, модель отсутствует, голос не загрузился: понятный статус и возможность повтора без зависания.
- [ ] Потребление GUI в покое, свёрнутом состоянии и трее; отсутствие лишних таймеров/аудиопотоков.
- [ ] Длинные задачи, много элементов, маленькое окно, прокрутка и доступность клавиатурой.
- [ ] Обезличенный диагностический отчёт только по запросу пользователя.

## 4. После стабилизации

- Короткий мастер первого запуска: микрофон → проба голоса → Ollama (можно пропустить).
- Разделение базовой установки и тяжёлых компонентов на явно выбираемые пакеты.
- Новые виджеты и настройка Главной без обязательных карточек/чата на стартовом экране.
- Дальнейшая интерактивность центра — без потери минимализма и роста фоновой нагрузки.

Клонирование/обучение голоса и облачная озвучка не входят в согласованный ближайший объём.
