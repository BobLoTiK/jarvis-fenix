# Ближайшие действия: R0 / подготовка R1

Главная очередь — [PLAN](../PLAN.md). Детали целевого видения из трёх DOCX —
[Феникс × JASTIN × Uvoxus](PHOENIX_JASTIN_RECONCILIATION.md).
JASTIN — целевое видение работодателя; стремимся реализовать его максимально.
Это документационное согласование маршрута R0–R6, не выполненная миграция.

## 0. Что подготовлено и что ещё не принято

- Предыдущие AEC-сборки пользователь проверял на Windows: улучшение есть,
  самоперебивания полностью не устранены. «Х» в «их» — случай для проверки,
  а не доказанная причина. Удар микрофона учитывать как отдельный сценарий.
- Рабочая копия содержит удаление WinRT TTS и расширенную диагностику;
  пользовательская проверка именно этой версии ещё не выполнена.
  Обычный AEC — Piper; ручная PCM/AEC-диагностика — Piper и Silero;
  SAPI без PCM — только метаданные. Auto: Silero → Piper → SAPI.
  [Инструкция](AEC_LOCAL_DIAGNOSTICS.md).
- Проверки пока отложены по просьбе пользователя. Не начинать установку вместо
  планирования и не объявлять этот пакет установленным/принятым.
- Setup/чистая Windows также отложены, но остаются условием публичного релиза.
  [Надёжность запуска](WINDOWS_STARTUP_RELIABILITY.md),
  [Python/Ollama](BOOTSTRAP_PYTHON_OLLAMA_UPDATE.md).

## 1. Когда вернёмся к аудио: диагностика и один подтверждённый дефект

- [ ] Подготовить текущую версию к Windows-прогону, зафиксировать движок,
      устройство/настройки и состав исходников; старые ZIP не смешивать вслепую.
- [ ] Локальный явный сбор диагностики: echo-only (молчание пользователя),
      настоящее перебивание, «их»/сходные звуки в контексте, неподвижный микрофон
      и изменение акустического пути. Удар по столу — отдельный тест, не речь.
- [ ] Сопоставить render/capture/clean, gaps, задержку, отмену и триггер VAD.
      Не угадывать причину только по одному значению probability/similarity.
- [ ] Исправить подтверждённую причину и повторить те же сценарии: начало
      пользовательской фразы сохранено, Stop работает, собственных команд нет.
- [ ] Не добавлять запреты слов, произвольные пороги, mute во время TTS,
      драйвер/виртуальный кабель или второй тракт вместо диагностики.

Synthetic/portable тесты не заменяют живую Windows-приёмку AEC.

## 2. Следующий функциональный этап: baseline → ограниченный потоковый TTS

1. **Измерения и корреляция:** времена первого LLM chunk, безопасной фразы,
   готового PCM и начала звука; паузы, CPU/RAM, cold/warm median/p95.
   Связать запрос/реплику/ответ с профилем, отменой и deadline в существующих
   владельцах. Не строить новый event bus ради меток; не писать секреты в логи.
2. **Лёгкий пакет Piper:** явная установка, размер/лицензия, один активный голос,
   CPU-потоки и понятный fallback; не требовать системного голоса или GPU.
   Выбор пользователя и параметры Ollama не менять молча.
3. **Реальное перекрытие:** генерация Ollama продолжается во время синтеза/звука,
   небольшой bounded buffer, порядок и backpressure. Существующий speak_stream
   не выдавать за уже реализованный новый конвейер.
4. **Отмена:** один жизненный цикл ответа, Stop/barge-in останавливает плеер и
   непроговорённый остаток; нет поздней речи, zombie-worker и наложения плееров.
   Короткий плавный de-click хвост — только у активного PCM, не у всей очереди;
   один итоговый блок идёт в output и AEC reference. Длина по замерам, не
   обязательные 200–300 мс. Отмена сразу; повторный Stop не продлевает хвост,
   выход/аварийная остановка не ждут fade. Для SAPI/winsound не обещать PCM fade.
5. **Инварианты:** safety/finalize_stream, история, cmd_lock/_say_lock, общий
   PCM/nonverbal, ASR gate и подтверждения сохраняются.

Критерий: речь до конца длинного LLM-ответа, без потери/перестановки фраз,
корректная отмена и измеримый результат на целевых Windows-ПК. Ожидание всего
ответа ради снижения нагрузки отклонено. Бюджеты задаются после baseline.
Отдельно проверить реальную скорость Silero: не подменять sample rate и pitch.

## 3. Затем — надёжность, исправления, обучение и команды

- Сохранить прежние Б–Г/M4: исправления по реальному результату действия,
  подтверждение/просмотр/удаление выученного, откат, качество локальной памяти.
- В том же контракте уточнить риск по эффекту, привязку подтверждения к аргументам,
  профилю и TTL; обязательный check не ответил — отказ/уточнение, не снижение
  защиты. «В очереди», «выполнено», «отменено» и «результат неизвестен» различать.
- Отдельная задача усиления хранения пароля: соль/KDF/миграция/тесты вместо
  заявления, что текущий SHA-256 уже даёт современную защиту паролей.
- Data-only импорт/экспорт существующих команд: схема/версия, preview, конфликты,
  лимиты архива, атомарность и откат. Не запускать Python или pickle из пакета.
- Проверить микрофон после отключения/смены устройства/сна; честные ошибки Ollama
  и голоса, повтор без зависания; нагрузку GUI в покое/трее; клавиатуру и DPI.

## 4. Затем — целевые этапы JASTIN, не исключённый бэклог

- **R2:** контракты/протокол/шина, voice_core и skills boundaries, внутренний
  pilot → subprocess → внешний SDK. ZeroMQ и целевые ASR/intent adapters
  оценить в этом маршруте. Vosk wake/fallback сохраняется; сравнение основного
  Sherpa/GigaAM не запрещено, но текущий ASR не меняем до проверки.
- **R3:** четыре проверки/consensus, ECAPA/enrollment, Trust L0–L4. Mode E
  остаётся требованием для уточнения операций/полномочий и dry-run, не самовольно
  отклонённой функцией. Калибровка и безопасная реакция на шум/timeout обязательны.
- **R4:** storage interface и миграция JSON → SQLite/SQLCipher/DPAPI; backup,
  recovery/rollback, общие embeddings, контролируемое обучение и история.
- **R5:** capabilities/lifecycle SDK по образцу S3, граф сценариев/макросы/OCR,
  целевой GUI/dock, provider router и модели/голоса из видения. Выбор конкретного
  frontend/router и совместимости Uvoxus API согласовать. Readonly pilot —
  первый срез, не конечный объём. Внешний Python-процесс не OS sandbox.
- **R6:** поставка модулей/обновления/откат, чистая Windows и ресурсные бюджеты.
  Nuitka — отдельный A/B standalone; компиляция launcher не ускоряет ML из venv.

Сначала выбрать обязательный вертикальный срез с пользователем/работодателем;
сроки без согласования не обещать. Различия нынешнего кода и цели не означают
отказа от цели. Дополнительные Hermes/MCP/Telegram/VLM не добавлять автоматически
сверх согласованного видения. Изменения требований — на согласование.
